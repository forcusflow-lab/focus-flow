# タスク・習慣拡張の機能調査と設計判断

## 調査対象と確認結果

本メモでは、成熟したTodoアプリに見られる反復、サブタスク、目標進捗の設計パターンを、Focus Flowの「必須項目を完了するまで対象アプリを制限する」という中核体験に適合する範囲で整理する。機能を増やしすぎると解除条件が理解しにくくなるため、初期実装は**毎日・毎週の反復、完了可能なサブタスク、時間または回数の数値目標**に限定する。

| 調査対象 | 公式資料で確認したパターン | Focus Flowでの採用判断 |
|---|---|---|
| Todoistのサブタスク | 大きな作業をより小さな単位に分解し、階層化された作業として管理する。[1] | Todoには1階層のサブタスクを追加する。必須Todoは、未完了サブタスクがある間は完了できない。 |
| Todoistの反復タスク | 反復タスクを完了すると、追加操作なしで次回の日時へ移る。過去分を消化しても、次回は将来の日時に設定される。[2] | Todoは毎日または毎週を選択可能とし、完了時に次回の日付へ再生成する。予定を遡って大量生成する方式は採用しない。 |
| TickTickの習慣目標 | 習慣の目標には「すべて達成」と「一定量に到達」の概念がある。[3] | 習慣とTodoの進捗は、チェックだけでなく「回数」または「分」の数値で記録できるようにする。 |

## Focus Flowにおける単純化

時間・回数・サブタスクはすべて必須解除条件に使えるが、ユーザーが管理する入力は一画面に詰め込まない。登録時は通常の完了に加え、必要な場合だけ「数値の目標」「繰り返し」「サブタスク」を開く段階的な詳細設定にする。必須項目は、その目標値または全サブタスクを完了して初めて解除条件を満たす。

繰り返しは**毎日**と**毎週**だけに絞る。高度な自然言語日付、月次の複雑な規則、無制限の階層は、現在の集中ルールの理解を損ねるため実装対象から外す。
