# Focus Flow — Todo・習慣画面の再設計判断

**基準日：2026年8月15日。** 本メモは、TodoistとHabitNowの公開資料を参考に、Focus FlowのTodo・習慣を「必須項目を終え、選択したアプリへのアクセスを解除する」日次体験に最適化するための設計判断です。競合の著作物・画面表現は複製せず、問題解決の原則だけをクリーンルームで取り入れます。

## 調査から得た原則

Todoistは、**Today・Upcoming・優先度・カスタムフィルター**で、膨大なタスクから「今取り組むべきもの」を素早く絞り込む構造を採っています。特に、TodayとUpcomingでは優先度の高いタスクが上に現れるため、期限と優先度を同時に使って次の行動を選びやすくしています。[1] [2] 繰り返しタスクは、完了時に次の発生へ移り、利用者が再作成しなくてよい構造です。[3]

HabitNowは、習慣・Todo・日課を一つの製品内で扱い、日次記録、目標、継続記録、統計、ウィジェット、リマインダーを組み合わせています。[4] 一方でFocus Flowは、アプリ制限解除という明確な成果を持つため、カテゴリや詳細設定を増やしすぎるのではなく、**今日の達成・必須状態・数値進捗・継続の状況**が一目で分かる構造を優先します。

| 着眼点 | 参考にしたパターン | Focus Flowでの適用 |
| --- | --- | --- |
| 一覧の優先順位 | Today/Upcomingと優先度で「今」を先に表示 | Todoを、必須・期限超過・今日が期限・その他・完了済みに分け、同じ群では優先度と期限で整列する。 |
| 状態の可視化 | 優先度色と明確なグループ | 必須はロックの意味を持つ専用の視覚状態、期限は小さなチップ、進捗は行内の短いバーで示す。 |
| 習慣の記録 | 今日の記録、連続、目標、分析 | 習慣のカードを日次の操作中心にし、今日の達成・数値目標・連続・週間比率を同一面で確認できるようにする。 |
| 入力摩擦 | Quick Add、動的追加 | 追加ボタンは常に画面上部に置き、初回・空状態からの追加は必須を事前選択して案内と実際の結果を一致させる。 |
| 複雑性の抑制 | 専門的なフィルター/分析は必要な人向け | Focus Flowでは任意の高度なフィルター言語、プロジェクト、クラウド連携は増やさず、日次で必要な4群に限定する。 |

## 実装方針

Todo画面は、上部に今日の達成要約と表示フィルターを置きます。実行順は**必須かつ期限超過、必須かつ今日が期限、その他の未完了、完了済み**とし、完了済みは折りたたんで初期画面の密度を下げます。各行には完了操作、必須状態、優先度、期限、数値進捗、サブタスク進捗を整列させ、長いタイトルでも一目で状態が分かるようにします。

習慣画面は、最初に今日の達成数と必須習慣の残数を置き、習慣カードには日次の完了操作、週間のドット履歴、連続日数、数値目標の進捗、必須バッジを収めます。達成済みを下げる操作で、今日まだ必要な行動を常に上へ残します。

通知、テンプレート、クラウドバックアップ、詳細分析は価値があり得ますが、端末権限、データ取り扱い、サポート負荷、定着指標を確認してから別フェーズで検討します。今回、未検証の通知やクラウド同期を追加しません。
