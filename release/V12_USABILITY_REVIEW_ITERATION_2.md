# Focus Flow v12 — 実機指摘に基づくユーザビリティ再レビュー

## 1. 再レビューの契機

本人用Android APKの実機で、統合Widgetのカード、チェック領域、本文、補足、余白が正しく収まらない状態が報告された。続いて、Todoの完了チェック後に不要なTodo画面が開くこと、TodayからTodo・習慣の本文を押すと一覧タブを経由することが報告された。これらは見た目だけの問題ではなく、**操作の意図と結果が一対一になっていない**問題である。

## 2. 変更後の操作原則

| 利用者の意図 | 操作領域 | 許可する結果 | 許可しない結果 |
|---|---|---|---|
| 完了する／復元する | 44dp以上の本体チェック領域、48dpのWidgetチェック領域 | 状態だけを変更し、現在の一覧・Widget文脈を維持 | 詳細・一覧・別タブを開く |
| 内容を確認・編集する | Todo／習慣の本文、明示的な矢印、Widget行本文 | 該当項目の詳細を直接開く | 不要な中間一覧を表示する |
| Todayへ戻る | Today起点の詳細を閉じる・戻る | Todayへ一段階で戻る | Todo／習慣一覧への置換、アプリ終了 |
| 今日全体を確認する | Widgetのヘッダーまたは余白、遮断画面の主操作 | Todayを開く | Unmatched Route、曖昧な詳細画面 |

## 3. Widgetの新しい視覚・構造要件

Widgetの外枠は、ホーム画面のセルサイズに応じて利用可能な高さが変わる前提で設計する。行は、チェック用の48dp領域と本文領域を独立させる。本文はタイトルと補足を持てるが、短い通常項目にも補足行を予約してカードの高さをそろえるのではなく、**行高は内容に応じて安全に拡張する**。小さなWidgetで収まらない件数は、下端で切らず、ListViewでスクロールできる。

| 項目 | 要件 |
|---|---|
| 本文 | 短文・長文の双方でタイトルを読み取れる。長文は2行まで表示し、必要なら省略記号を使う。 |
| 補足 | 必須・時間帯・完了・ロックの情報を、本文と衝突させず、タイトルの下へ表示する。情報がないときは余白を作りすぎない。 |
| チェック | 視覚要素はコンパクトに保ちつつ、押下領域は48dpを維持する。本文カードとの重なりを作らない。 |
| 高さ | 行の高さを一律に固定せず、タイトル・補足の必要量を満たす最小高へ拡張する。 |
| サイズ | 小・標準・拡大のWidget、透明度0〜100%、明暗テーマ、項目0件〜多数件で破綻しない。 |

## 4. 全画面再監査の範囲

Today、Todo、習慣、メモ、振り返り、その他、設定、通知、Plus、利用条件、プライバシー、サポート、起動、集中制限、Widget、Deep Link、戻る、空・読み込み・失敗状態を対象とする。各対象で、次の組合せを確認する。

| 観点 | 代表状態 |
|---|---|
| サイズ | 小画面・標準画面・大画面、Widget小・標準・拡大 |
| 文字量 | 空、短文、長文、必須・時間帯・期限・進捗など補足あり |
| 操作 | 完了、復元、本文詳細、削除、保存、戻る、Deep Link、外部権限導線 |
| 状態 | 初回、読み込み、未登録、未許可、時間帯前・中・後、完了、上限、購入失敗、ネイティブ連携失敗 |

## 5. 修正の優先順位

最優先は、Widgetの重なり・切れ、チェックによる不要な画面遷移、Todayからの一覧経由遷移である。次に、Todo・習慣・設定を基準に、カードの可変高さ、本文幅、補足行、削除・戻るのタップ領域をそろえる。その他画面は、同じ可変レイアウト・一操作一結果・起点へ戻る原則に照らして修正する。

## 6. コード再監査の記録

| 対象 | 再監査結果 | 対応方針 | 実機で残る確認 |
|---|---|---|---|
| Today | 本文が一覧タブへ遷移してから詳細を開く実装だった。 | Today内のTodo／習慣フォームを直接開くよう変更し、閉じるとToday文脈を維持する。 | 本文・矢印・チェック・Android戻るを個別に確認する。 |
| Todo・習慣 | チェックと本文は構造上別の操作領域だが、実機報告を受けて成功・失敗・復元の全状態を再受入対象にした。 | チェックは状態更新だけ、本文は詳細だけという静的回帰を追加する。 | 時間前ロック、進捗、サブタスク、長文の操作を確認する。 |
| Android Widget | 固定56dp行と空の補足行予約が、少数項目・可変セルで不自然な空白と視覚的なずれを生む。 | 行を内容に応じる最小68dpへ変更し、空の補足を`GONE`にして48dpチェックと2行本文を分離する。 | 小・標準・拡大サイズ、透明度、短文・長文、必須・通常、完了・未完了を確認する。 |
| 設定 | 画面内戻るはあるが、Android物理戻るで詳細パネルを設定ホームへ戻す明示処理がなかった。 | 詳細パネル表示中はAndroid戻るを捕捉して設定ホームへ戻す。 | 集中制限・表示・通知・Plusの各詳細で戻るを確認する。 |
| メモ | フォームはキーボード回避、可変本文、閉じるを備える。 | 現行構造を維持する。 | 長文・空タイトル・キーボード・Todo化・削除を確認する。 |
| 振り返り・その他 | カードと数値領域は縮小可能な幅を持ち、遷移先は明示されている。 | 現行構造を維持する。 | データなし、長い文言、表示倍率で確認する。 |
| 法務・プライバシー・サポート | スクロール、戻る、長文カード、削除確認、FAQ開閉、報告共有の基本構造を確認した。 | 現行構造を維持する。 | 日本語／英語、長文、共有失敗、削除取消を確認する。 |
| 起動・遮断・Deep Link | 全画面導入、authorityなしURI、Today遷移の構造を再確認した。 | URI規約を維持し、Widgetと遮断画面を実機再受入する。 | アプリ停止中・起動中、通常版・本人用版、Android戻るを確認する。 |

## 7. 合格条件

自動テスト、通常版・本人用版のクリーンAndroid生成、署名ビルドに加え、Android実機でDEV-01〜DEV-14を実施する。実機結果が未記録の項目は合格ではない。Google Play内部テストへの再配布は、この受入を終え、所有者が確認した後にだけ行う。
