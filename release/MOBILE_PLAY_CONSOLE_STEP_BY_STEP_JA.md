# Focus Flow：スマホのChromeで進めるGoogle Play Console登録ガイド

> **この手順では、まだ「本番公開」や「審査への送信」は行いません。** 目的は、Focus FlowをGoogle Play Consoleへ正しく登録し、クローズドテストを開始できる状態まで整えることです。端末はAndroidスマホ、ブラウザはChromeを前提にしています。

## まず準備するもの

Chromeで [Google Play Console](https://play.google.com/console/) を開く前に、次の情報を手元に用意してください。スマホ画面では入力欄が狭いため、長い文章はGoogle Keepやメモにコピーしておくと安全です。

| 項目 | Focus Flowで使う内容 | 注意点 |
| --- | --- | --- |
| Googleアカウント | 公開主体として使うGoogleアカウント | 個人用と事業用を分ける場合は、将来も継続して管理できる方を選びます。 |
| アプリ名 | **Focus Flow** | ストア上の表示名は後から調整できます。まずは短く明確な名称にします。 |
| Androidパッケージ名 | **`com.app.focusflow`** | Google Play上で一度使うと、同じ名前を別アプリへ再利用できません。既存アプリとして作成済みかを確認してから進めます。[1] |
| 公開サポートメール | あなたが実際に確認できるメールアドレス | 後でストア掲載とプライバシーポリシーに同じ連絡先を使います。仮のメールアドレスは入力しません。 |
| 発行主体名 | 実名または事業者名 | プライバシーポリシーの発行主体と一致させます。 |
| 配布ファイル | **Android App Bundle（`.aab`）** | Google Playではアプリの配布にApp Bundleを使います。APKではなく、後で用意する`.aab`をアップロードします。[1] |

## 0. スマホで見やすくする

1. Chromeで `https://play.google.com/console/` を開きます。
2. 画面右上のChromeメニュー（`︙`）を開き、**「PC版サイト」**をオンにします。Google Play Consoleの一部の項目はPC表示の方が操作しやすいためです。
3. 公開主体として使うGoogleアカウントでログインします。初回なら、Googleの案内に従ってPlay Consoleデベロッパーアカウントを作成します。利用規約への同意、登録料の支払い、アカウント種別、本人確認が求められることがあります。[2]

> **ここで止めてよい場面**：登録料の決済、本人確認、法的な氏名・住所などの入力は、あなた自身の情報に基づいて行う必要があります。内容を確認してから進めてください。

## 1. Play ConsoleでFocus Flowを作成する

ログイン後、左上の**「すべてのアプリ」**またはホーム画面から、次の順で進みます。

1. **「アプリを作成」**（Create app）をタップします。
2. 基本情報を次のように入力します。

| 画面の項目 | 入力・選択内容 |
| --- | --- |
| デフォルトの言語 | **English (United States)** を推奨します。世界向けの基本掲載情報を英語にし、日本語は後で追加します。 |
| アプリ名 | **Focus Flow** |
| アプリまたはゲーム | **アプリ** |
| 無料または有料 | **無料**。初期ベータでは購入を求めず、課金はGoogle Play Billingの検証後に追加します。 |
| ユーザー向け連絡先メール | あなたが毎日確認できる実在の公開サポートメール |
| デベロッパー ポリシー／輸出法 | 内容を読み、事実に基づいて同意します。 |
| Play App Signing | 規約を確認して同意します。 |

3. **「アプリを作成」**をタップします。Google Playの公式手順でも、アプリ名・種別・無料／有料・公開連絡先・各宣言を入力して作成する流れです。[1]

作成後は、Focus Flowの**ダッシュボード**が開きます。ここに未完了の必須設定が表示されます。緑のチェックが付くまで、上から順に埋めていけば大丈夫です。[3]

## 2. 最初に入力するストア情報

左メニューから **「成長」→「ストアの表示」→「メインのストアの掲載情報」**（画面表記は更新される場合があります）を開きます。以下は、現在のFocus Flow向けに準備した内容です。

| 項目 | まず入れる内容 |
| --- | --- |
| アプリ名 | Focus Flow |
| 短い説明 | `Finish your must-dos, then unlock the apps that distract you.` |
| カテゴリ | **Productivity** |
| 連絡先メール | 手順0で決めた実在の公開サポートメール |
| プライバシーポリシーURL | **まだ入力しない**。発行主体名・連絡先を確定し、HTTPSで公開してから入力します。 |

英語の長い説明文は、プロジェクト内の `release/GOOGLE_PLAY_STORE_LISTING_EN.md` に準備済みです。貼り付ける際は、見出しや箇条書きが崩れていないか確認してください。

**画像は今すぐ必須ではありません。** ただし、クローズドテストのリンクを共有する前に、最低限のアプリアイコン、スクリーンショット、説明文を揃えると、テスターが内容を理解しやすくなります。ストア掲載情報はテストトラック間でも共有されます。[1]

## 3. アプリのコンテンツを設定する

ダッシュボードの**「アプリのコンテンツ」**を開き、未完了項目を順に確認します。回答はリリース版の実装と一致していなければなりません。Focus Flowで重要なのは次の3点です。

| 設定項目 | Focus Flowでの考え方 |
| --- | --- |
| アプリのアクセス | ログイン必須ではありません。テスターがTodo、習慣、設定まで利用できることを確認します。アクセシビリティはAndroidの設定画面で**任意**に有効化します。 |
| 広告 | 現在のベータには広告SDK・行動追跡SDKを含めない設計です。最終ビルドに広告を追加しない限り、広告なしとして回答します。 |
| Data safety | Todo、習慣、メモ、日課ルール、表示設定は端末内保存です。最終的には、署名済みビルドと全SDKを確認したうえで入力します。推測で確定しません。 |
| アクセシビリティ | 選択アプリが前面化したことを検知してルールを適用する用途です。画面文字・メッセージ・入力内容・スクリーンショットを読み取らず、機能は任意でいつでも無効化できる、と実装どおりに説明します。 |

> **送信前の注意**：プライバシーポリシーURL、Data safety、AccessibilityServiceの申告は、公開サポートメールと発行主体名が決まり、最終ビルドを確認してから確定します。ここは「とりあえず選ぶ」項目ではありません。

## 4. まず内部テストを作る

本命のクローズドテストの前に、少人数で**内部テスト**を行います。Google Playでは内部テストに最大100人を追加でき、アプリ設定をすべて完了する前でも初期品質確認に使えます。[4]

1. 左メニューから **「テスト」→「内部テスト」**を開きます。
2. **「新しいリリースを作成」**をタップします。
3. 後で用意する `.aab` ファイルをアップロードします。**APKはアップロードしません。**
4. リリース名を `0.1.0-internal` のように分かる名前にし、リリースノートは次を使います。

```text
Initial Focus Flow internal beta.
Please test required To-dos, habits, schedules, AccessibilityService disclosure, and selected-app restriction.
```

5. テスター欄に、自分を含む2〜5件のGoogleアカウントを追加します。
6. エラーがなければ、**内部テストに保存**します。この操作は本番公開ではありません。

## 5. クローズドテストを作る

内部テストで致命的な問題がないことを確認したら、**「テスト」→「クローズドテスト」**を開きます。

1. 既定のクローズドトラックを開くか、必要なら `Focus Flow Closed Beta` という名前でトラックを作成します。
2. テスター管理で、メールアドレスのリストまたはGoogleグループを選びます。テスターはGoogleアカウントまたはGoogle Workspaceアカウントを使う必要があります。[4]
3. 初回は**12人以上**を招待します。個人デベロッパーアカウントが2023年11月13日以降に作成された場合、Google Playの本番アクセス申請には、少なくとも12人が14日間連続でクローズドテストへオプトインしている必要があります。[5]
4. 新しいリリースを作成し、内部テストで確認した `.aab` を追加します。
5. リリースノートを入力し、保存します。
6. **「テスター向けに公開」**に相当するクローズドテストの公開操作を行います。これはクローズドテストへの配布であり、本番公開ではありません。

テストリンクは反映まで数時間かかることがあります。クローズドテストのアプリはGoogle Play検索で通常見つからないため、テスターにはPlay Store URLまたはオプトインリンクを共有します。[4]

## 6. テスターへ送る案内文

クローズドテストを公開したら、次の文章にオプトインリンクを付けて12人以上へ送ります。

```text
Focus FlowのAndroidクローズドテストです。
必須Todo・習慣を完了するまで、選んだアプリを制限する生産性アプリです。

1. このリンクを開いてテスターに参加してください。
2. Google PlayからFocus Flowをインストールしてください。
3. 必須Todoを1件作り、制限対象アプリを1つ選んでください。
4. アクセシビリティの説明を読み、必要ならAndroid設定から有効化してください。
5. 使いにくい点・誤った制限・解除できない状態があれば、端末名、Androidバージョン、再現手順を添えて教えてください。

重要：本番アクセス申請の条件に関係するため、参加後14日間はテストへの参加を解除しないでください。
```

## 7. 今は押さないボタン

次の操作は、ベータ運用・プライバシー公開・審査資料が整い、あなたが明示的に公開を判断するまで行いません。

| 操作 | 今は行わない理由 |
| --- | --- |
| **本番環境へロールアウト** | 一般公開につながります。 |
| **審査に送信** | Data safety、プライバシーポリシー、アクセシビリティ申告が確定後に行います。 |
| **有料化／サブスクリプションの有効化** | Google Play Billingの実装と購入テスト完了後に行います。 |

## 8. このガイドを終えた時点の到達目標

この順番で進めると、Focus Flowは「Play Consoleに登録済み」「内部テストで初期確認済み」「クローズドテストに12人以上を招待済み」という状態になります。その後は14日間のテスターオプトインを維持しつつ、バグ報告を記録・修正し、必要になった時点で本番アクセスを申請します。[5]
