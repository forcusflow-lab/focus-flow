# Focus Flow v18 / 高密度一覧カード・テーマ整合性 再設計仕様

**記録日:** 2026-08-26  
**起点:** 本人用v7はWidgetの追加・操作には合格したが、実機で補足テキストの切れ、行間の不均衡、過大な暗い面、一覧としての階層不明瞭さが残った。アプリ本体とWidgetのライト／ダークにも文字・面・境界の低コントラストおよびテーマ反映漏れがある。

## 1. 参照から採用する設計原則

Material Designは、カードを単一の主題とアクションのために用い、利用者が素早く走査できる明確な階層を置くこと、単純な階層で済む場合にカードを濫用しないこと、関連する一覧ではinset dividerで項目を分けることを示している。[1] Android Widgetsは、Android 12以降でDay/Nightまたはdynamic color themeを使い、テーマ属性をルート・子要素へ適用することでライト／ダークを一貫させられるとしている。[2]

> Widgetは「大きな濃色の容器に行を置く」構成ではなく、**小さなヘッダーと、均一な行を区切る軽い一覧面**として扱う。装飾は情報・操作の識別を助ける分だけ使い、本文領域を犠牲にしない。

## 2. v18 Widgetデザイン案

| 領域 | レイアウト | 視覚規則 | 操作 |
|---|---|---|---|
| 外側コンテナ | 角丸16dp、12dp内側余白 | 不透明度設定を反映。ライトは明るいsurface、ダークは暗いsurface。高いコントラストの外枠を使う | ヘッダー・余白はTodayへ遷移 |
| ヘッダー | 32dp、左に「今日の項目」、右に状態 | タイトル12sp semibold、状態10sp。説明は1行だけ | Todayへ遷移 |
| 一覧面 | ヘッダー下に連続した最大2行 | 行は48dp、行間0dp、2行目だけinset divider。個別の暗いカードは使わない | 本文は詳細へ遷移 |
| チェック | 48dpタップ領域、中央20dp視覚チェック | 未完了はoutline、完了はaccent fill＋白チェック。ロックは同位置に小アイコン | 完了／復元だけ |
| タイトル | チェックの右、横幅を最大化 | 13sp、1行、省略。完了は取り消し線＋適度な減衰 | 詳細へ遷移 |
| 補足 | タイトルの下、必要時のみ | 10sp、必須は短いaccent pill、時間帯はmuted text。収まり切らない補足は表示しない | なし |

この案は参考画像の「見出し＋連続した均一行＋細い区切り＋小さな選択コントロール」という密度を採用し、参考画像固有のイラスト・色・進捗指標はFocus Flowへ持ち込まない。

## 3. ライト／ダークテーマ契約

| トークン | ライト | ダーク | 用途 |
|---|---|---|---|
| `widgetSurface` | `#F8FBF9` | `#17231E` | Widgetと一覧の面 |
| `widgetOnSurface` | `#13251F` | `#F4FBF7` | 見出し・本文 |
| `widgetMuted` | `#4E655B` | `#B7CCC2` | 状態・時間帯 |
| `widgetDivider` | `#D8E3DC` | `#355047` | inset divider・境界 |
| `widgetAccent` | テーマprimary | テーマprimary | 完了・必須だけ |

アプリ本体の各画面は`useFocusPalette`または同等の意味トークンだけを使い、固定のライト背景・本文・境界を持ち込まない。Widgetはアプリ外観設定と端末Day/Nightを明示的に同期し、テーマが変わった時点で全Widgetを再描画する。アプリ本体・Widget双方で本文、補足、入力、境界、必須、完了、無効、空、読み込み、エラーをライト／ダークの組合せで検査する。

## 4. レビュー観点と反復品質ゲート

| フェーズ | 判定項目 | 不合格時の対応 |
|---|---|---|
| 設計レビュー | 情報階層、最大行数、長文、必須／時間帯、操作領域、テーマトークン | 仕様を修正してから実装へ進む |
| 静的テスト | 20dp視覚チェック、48dp操作領域、inset divider、固定色禁止、ID／Intent一意性 | テスト先行で修正 |
| ネイティブ生成 | Manifest、RemoteViews、resource、ライト／ダーク資産、署名 | クリーンprebuild・APK解析で再確認 |
| 実機受入 | 小／中／大、1件／2件、短文／長文、必須／時間帯、完了／復元、ライト／ダーク、文字サイズ | 崩れ・低コントラスト・誤操作が1件でもあれば設計へ戻る |

## 5. 現行実装レビューと採用判断

| レビュー対象 | 現行の問題 | v18の判断 |
|---|---|---|
| Widget root | パレット`background`をWidget全高へ塗っており、項目が2件でも濃い大きな空白面が残る | rootは透明。内容がある領域だけを内側一覧カードとして描く |
| 行の補足 | タイトルと補足を常に縦積みし、48dp行内で補足が切れやすい | タイトルを第一優先、補足は短いタグ／時間帯だけ。長い補足は非表示にする |
| 行の境界 | 1dp余白のみで、連続リストの区切りが弱い | 2行目の上だけにinset dividerを置く。個別の濃色カードは使わない |
| Widget色 | rootがapp paletteの`background`をそのまま使い、ライト／ダークのsurface階層と一致しない | light／dark別のneutral card surface・onSurface・dividerを明示。primaryは必須・完了だけに限定 |
| 共通UI | `ui.tsx`のStyleSheetに白系surface、border、empty stateが残り、呼び出し側のpalette指定で上書きされない箇所がある | 共通UIのsurface／border／empty／iconButtonをpalette必須へ変更する |
| 主要画面 | Today、習慣、振り返り、その他、設定に固定ライト色が残り、darkで可読性が下がる | 固定色監査表を作り、画面ごとにpaletteへ移行して静的テストを追加する |
| 起動 | 起動画面はappearanceに関係なく濃い緑で、テーマ反映の期待とずれる | 起動画面はブランド固定として扱うか、appearance別の面・StatusBarを実装するかを設計レビューで決定する |

**採用デザイン:** Widgetは、外側を透明に保ち、上端へ角丸16dpの`listCard`を置く。`listCard`は32dpヘッダーと最大2件の連続行で高さを決める。行は白／暗色の同一surface上に並び、2行目のみに12dp inset dividerを置く。チェックは48dpタップ領域の中央20dp、本文は13sp、補足は10spの短いタグだけとする。これにより、参考デザインのような「明快なヘッダー＋均一な連続リスト」を実現し、Widget外側の余白をカード面として見せない。
