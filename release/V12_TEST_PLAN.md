# Focus Flow v12 — テスト計画・品質ゲート

## 1. 目的

本計画は、v12の時間帯必須、遮断画面、ウィジェット、起動画面、全画面操作導線を、実装後に同じ順序で検証するための基準である。自動テストで確認できる仕様と、Android実機でしか確認できないホーム画面・アクセシビリティ・起動挙動を明確に分け、未検証の状態を合格と扱わない。

## 2. 品質ゲート

| ゲート | 実行時点 | 必須結果 | 失敗時の扱い |
|---|---|---|---|
| G1：データ・ロジック | 時間帯必須の実装直後 | 境界時刻、曜日、日跨ぎ、移行、削除のVitestが成功 | 実装を修正し、影響する既存テストも再実行 |
| G2：画面・遷移 | フォーム、Today、設定、起動画面、Deep Link実装後 | UI静的回帰、チェック・詳細・戻るの操作分離、TypeScriptが成功 | 仕様との不一致を設計書へ戻して修正 |
| G3：Android生成 | ネイティブテンプレート変更後 | 通常版・本人用版の`expo prebuild --clean`で、URI・Receiver・Manifestに加えWidgetの行高・タップ領域・本文制約を確認 | プラグインまたはテンプレートを修正して再生成 |
| G4：全自動回帰 | 実装完了後 | `pnpm check`、`pnpm lint`、全Vitestが成功 | 不具合票を追加し、修正後に全範囲を再実行 |
| G5：署名ビルド | 自動回帰合格後 | GitHub Actionsで署名済みAPK/AABを生成、成果物整合性を確認 | ログから原因を特定し、再ビルド |
| G6：Android実機受入 | 署名ビルド後 | 時間帯・遮断・ウィジェット・起動・戻るの全項目を通過 | 内部テスト再配布を行わず、不具合修正へ戻る |

## 3. 自動テストケース

| ID | 対象 | 前提／操作 | 期待結果 |
|---|---|---|---|
| TW-01 | 常時必須 | `requiredWindowMode=always`の未完了Todoを作る | 時間帯の有無にかかわらず解除条件へ入る |
| TW-02 | 時間帯必須 | 19:00–21:00に割当済みTodoを18:59で判定 | Todayは「この後」、解除条件・遮断対象から外れる |
| TW-03 | 時間帯必須 | 同じTodoを19:00で判定 | Todayは「今やる」、解除条件・遮断対象へ入る |
| TW-04 | 時間帯必須 | 同じTodoを21:00で判定 | 時間帯外として解除条件から外れる |
| TW-05 | 日跨ぎ | 22:00–06:00を23:00と翌01:00で判定 | 両方で必須として扱う |
| TW-06 | 複数割当 | 朝・夜の二つをTodoへ割当 | どちらか一つが有効なら必須として扱う |
| TW-07 | 旧データ移行 | `isRequired=true`だが時間帯フィールドなし | `always`へ正規化し既存挙動を保持 |
| TW-08 | 時間帯削除 | 割当済み時間帯を削除 | 影響項目を`always`へ安全にフォールバック |
| DL-01 | 遮断画面 | 主ボタンのIntentを生成 | `<scheme>:///`でTodayを開く。authority形式を含まない |
| DL-02 | ウィジェット詳細 | Todo/Habit行本文のIntentを生成 | `<scheme>:///todos?open=`／`<scheme>:///habits?open=` |
| DL-03 | ウィジェット完了 | 48dpチェック領域を押す | complete／restoreだけを実行し、画面遷移しない |
| UI-01 | フォーム | 必須をオフ・オン・時間帯選択 | 必須オン時だけ実行時間帯が現れ、選択結果を要約する |
| UI-02 | Today | 時間帯外・内・完了 | 「この後」「今やる」「完了」を文字とアイコンで区別する |
| UI-03 | 起動 | 保存データの復元を完了 | 全画面導入がフェードし、不要な待機やアイコン単体表示が残らない |
| UI-04 | 戻る | 設定、詳細、モーダルを閉じる | 直前の画面またはTodayへ一階層ずつ戻る |
| UI-05 | 完了操作の分離 | Today、Todo、習慣のチェック操作を静的に検査 | チェックのハンドラは状態更新だけを担い、詳細遷移のハンドラを呼ばない |
| UI-06 | Today直接詳細 | TodayのTodo／習慣本文を押す | 一覧タブを中間表示せず該当詳細を開き、閉じるとTodayへ戻る起点情報を保持する |
| W-01 | Widget行制約 | RemoteViews行のXMLを検査 | 48dpチェック領域、本文の最小幅、1行タイトル、必要時だけの補足、区切り線が高密度リストを維持し、独立カードや空補足行を作らない |
| W-02 | Widget本体制約 | Widget shellとprovider metadataを検査 | ヘッダー・リスト・空状態が小・標準・拡大サイズで残余高を安全に使い、一覧をスクロールできる |
| W-03 | Widget文字サイズ | Android同期状態とRemoteViewsのサイズ処理を検査 | `fontScale`のcompact・standard・largeがTodo・習慣の双方へ同じ規則で渡り、タイトル・補足・行高が連動する |
| W-04 | Widgetテーマ | Widget Provider・行描画を検査 | ライト・ダーク両方の面、本文、補足、境界、必須、完了、ロックのパレットを使い、ライト専用の固定本文色を残さない |
| W-00 | Widget登録安全層 | Provider metadata、初期情報XML、初期レイアウト、例外時フォールバックを検査 | ピッカーの初回追加はCollection更新へ依存しない`initialLayout`を持ち、metadata resourceが初期情報XMLと最小RemoteViewsへ解決される。更新例外時もTodayへ戻れるフォールバック面を更新する |
| DM-01 | 全画面テーマ契約 | 共通UIと全画面の静的配色を検査 | 固定のライト専用背景・本文・補足・入力色をテーマトークンまたはライト・ダーク両対応の意味色へ置換する |

## 4. 実行コマンドと記録

| 順序 | コマンド／作業 | 記録する証跡 |
|---|---|---|
| 1 | `pnpm check` | TypeScript結果 |
| 2 | `pnpm lint` | ESLint結果 |
| 3 | `pnpm vitest run` | 全テストの成功・スキップ・失敗件数 |
| 4 | `CI=1 npx expo prebuild --platform android --clean --no-install` | 通常版のManifest・Kotlin・資産生成 |
| 5 | `FOCUS_FLOW_PERSONAL_UNLIMITED=1 CI=1 npx expo prebuild --platform android --clean --no-install` | 本人用の別パッケージ・Deep Link・versionCode |
| 6 | GitHub Actions署名ビルド | ワークフローRun、APK/AAB、署名・ZIP整合性 |
| 7 | Android実機受入 | 下記手順の項目別結果、端末種別、OS、ビルド番号 |

## 5. Android実機受入テスト

| ID | 手順 | 合格条件 |
|---|---|---|
| DEV-01 | 起動する | 全画面のブランド導入からTodayへ自然に遷移する |
| DEV-02 | 必須Todoに19:00–21:00を割り当て、18:59に制限アプリを開く | 制限されず、Todayに開始予定が表示される |
| DEV-03 | 19:00以後に同じ制限アプリを開く | 遮断画面が表示される |
| DEV-04 | 遮断画面の主ボタンを押す | Unmatched Routeにならず、必ずTodayを開く |
| DEV-05 | ウィジェットのチェックを押す | 完了し、アプリ画面を開かない |
| DEV-06 | 完了済みチェックを押す | 復元し、アプリ画面を開かない |
| DEV-07 | ウィジェットの行本文を押す | 該当Todo／習慣の詳細を開く |
| DEV-08 | ウィジェットのヘッダー余白を押す | Todayを開く |
| DEV-09 | Todo／習慣本体のチェックを押す | 詳細へ遷移せず、完了／復元だけが起きる |
| DEV-10 | 設定・詳細・モーダルから戻る | 直前の画面へ戻り、唐突なタブ移動や終了がない。設定内詳細ではAndroid戻るで設定ホームへ戻る |
| DEV-11 | Widgetを小・標準・拡大へリサイズし、短文・長文、必須・通常、完了・未完了を表示する | チェック、本文、補足、見出し、余白に重なり・切れ・過剰な空白がなく、一覧はスクロールできる |
| DEV-12 | TodayのTodo／習慣のチェックを押す | 完了／復元だけが起き、Todo／習慣の詳細や一覧を開かない |
| DEV-13 | TodayのTodo／習慣の本文と矢印を押し、詳細を閉じる | 該当詳細を直接開き、中間の一覧タブを表示せず、閉じる・戻るでTodayへ戻る |
| DEV-14 | Todo／習慣一覧で、短文・長文、必須・通常、進捗・サブタスクあり・なしを表示する | カード、チェック、本文、補足、削除が重ならず、完了操作後も同じ一覧文脈を保つ |
| DEV-15 | Widgetをlight・dark、文字サイズcompact・standard・largeで表示する | Todo・習慣の文字サイズと行高が同じ規則で変わり、チェックは行中央、標準Widgetでは見出し以外に2件以上を表示する |
| DEV-16 | Today、Todo、習慣、メモ、振り返り、その他、設定、Plus、法務、プライバシー、サポート、モーダル、空・読み込み・エラーをdarkで開く | 本文、補足、入力、境界、ボタン、無効状態が背景と識別でき、操作目的が読める |
| DEV-17 | ホーム画面を長押しし、Widgetsから`Focus Flow · Today`を追加する | 「ウィジェットを追加できませんでした」が表示されない。初期安全面または一覧が表示され、白紙・クラッシュにならない |
| DEV-18 | 追加直後にアプリを開き、Widgetへ戻る | 初期面またはフォールバック面が表示された場合もTodayへ復帰でき、同期完了後はCollection一覧へ更新される |
| DEV-19 | Widgetをlight・darkの両方で表示する | 見出し、本文、補足、必須、時間帯、境界、チェックが背景から識別できる。ライトモードで本文が消えない |

## 6. 不具合処理手順

不具合が見つかったら、再現手順、期待結果、実際の結果、対象ビルド、端末・OS、画面またはログを記録する。修正は最小の影響範囲で行い、該当テストに回帰ケースを追加する。修正後は失敗したテストだけでなく、G4の全自動回帰と関連するG3のクリーン生成を再実行する。G6の実機項目は修正版で再確認されるまで合格に変更しない。
