# Focus Flow v12 — 全面UX再設計 仕様書・設計書

## 1. 目的と完了条件

Focus Flowは、Todo、習慣、集中制限を一つの流れで扱うローカルファーストのアプリである。本改修では、高校生から60代までが説明を読まなくても「**今日、何をすればよいか**」「**いつ取り組むべきか**」「**なぜアプリが制限されているか**」を理解できる状態を目標とする。画面を増やすことではなく、行動の判断を減らし、完了・復元・詳細・戻るの結果を常に予測できることを優先する。

> **完了条件**：Todo・習慣に既存の集中制限時間帯を割り当てられ、該当時間帯だけ未完了項目が制限解除条件になる。遮断画面とウィジェットはTodayまたは該当項目へ誤りなく遷移し、起動から完了まで同じフラットな視覚言語で利用できる。自動テスト、Androidクリーン生成、署名ビルドを通過し、実機受入項目が明文化される。

| 成果 | 判定基準 |
|---|---|
| 時間帯必須 | 必須Todo・習慣で既存の集中時間帯を選択でき、時間帯の内外で集中制限の対象判定が変わる |
| 遮断画面 | 「Focus Flowで項目を確認する」は必ずTodayを開く。項目タップは該当Todo／習慣の編集画面を開く |
| 起動体験 | アイコン単体の見え方ではなく、短時間の全画面ブランド導入からTodayへ自然に移る |
| 操作の一貫性 | チェックは完了／復元だけ、本文は詳細、戻るは直前の画面に戻る。44pt相当以上の操作領域を確保する |
| 品質 | 単体・統合・ネイティブ生成・署名ビルドの結果を記録し、実機でしか確認できない項目は未検証として区別する |

## 2. 対象範囲と非対象

本改修はAndroidを優先し、iOSでもデータモデルとアプリ内画面を共通化する。無料・Plusの件数上限、既存の分課金、ローカル保存、アクセシビリティを用いるAndroid集中制限は維持する。クラウド同期、ユーザー登録、位置情報、通知の増設、端末管理者権限による強制制御は対象外とする。

| 対象 | 方針 |
|---|---|
| Todo・習慣 | 必須指定に加えて、既存の集中時間帯を選ぶ「実行時間帯」を追加する |
| Today | 今すぐ必要な項目、後で始まる項目、通常項目を一度に読める短い階層へ整理する |
| 集中制限 | 選択中の時間帯に未完了の必須項目があるときだけ、選択アプリを遮断する |
| ウィジェット | 完了・復元、Today、項目詳細のタップ領域を明確に分離し、時間帯ラベルを表示する |
| 起動 | ネイティブスプラッシュの直後に全画面の軽量ブランド導入を出し、状態復元後にTodayへフェードする |
| 設定 | 集中制限の時間帯を一箇所で管理し、各Todo・習慣はその名称を選ぶだけにする |

## 3. 情報設計と画面設計

画面は縦向き9:16、片手操作、読みやすい標準文字サイズを基準とする。各画面では一つの意思決定だけを先に置き、補足は必要なときだけ展開する。色は状態の補助であり、必須・時間帯・警告の意味を文字とアイコンでも伝える。

| 画面 | 主要内容 | 操作設計 | 状態表示 |
|---|---|---|---|
| 全画面起動 | 深緑から霧白へ移る背景、Focus Flow、短いメッセージ | 操作なし。保存データの復元完了で自然に消える | ローディング表示を常設せず、300ms程度のフェードのみ |
| 今日 | 「今やる」「この後」「通常」の順に連続表示するカード群 | チェックは完了・復元、本文は詳細、追加は右上 | 時間帯中は時計ラベル、開始前は「19:00から」、完了は読みやすい取消線 |
| Todo／習慣作成 | 基本情報、必須、実行時間帯、詳細設定 | 必須をオンにした時だけ時間帯選択を表示。既存の集中時間帯を複数選べる | 未選択は「いつでも必須」、選択済みは名称と時刻を要約 |
| 集中制限 | 有効状態、制限アプリ、時間帯の管理 | 時間帯を作成・変更・削除。項目ごとの割当はTodo／習慣側で行う | 現在有効な時間帯と未完了数を一行で示す |
| 遮断画面 | 制限理由、未完了数、Todayへの主操作 | 主ボタンは常にToday。アプリ情報は通常モードだけ補助導線 | 「19:00–21:00の必須項目が残っています」のように理由を具体化 |
| ウィジェット | 直近の必須・通常項目、背景濃さ、完了表示 | 左の48dp領域は完了・復元、本文は詳細、余白はToday | 「必須」「19:00–21:00」「完了」などを小さく文字で併記 |
| 設定 | 表示・言語、集中制限、通知、ヘルプ | 目的別の一階層。戻るは設定ホームへ戻る | Android限定機能はiPhoneと明確に分離して説明 |

## 4. 時間帯必須機能の仕様

### 4.1 ユーザー向けの表現

機能名は **「実行時間帯」** とする。必須にしたTodo・習慣だけに表示し、説明は「この時間帯は、完了するまで選んだアプリを使えません」と短くする。時間を直接重複入力させず、集中制限で作成済みの時間帯を選択する。これにより、時間の意味と制限対象が画面ごとにずれない。

| 選択状態 | 保存値 | ふるまい |
|---|---|---|
| いつでも | `requiredWindowMode: "always"` | 必須項目として常に集中制限の解除条件に含める |
| 時間帯を選ぶ | `requiredWindowMode: "scheduled"` と `requiredScheduleIds` | 選んだ時間帯のいずれかが有効な時だけ、集中制限の解除条件に含める |
| 必須ではない | `isRequired: false` | 時間帯選択は表示しない。集中制限の解除条件には含めない |

同じ項目に複数の時間帯を選べる。例えば「平日朝」「平日夜」のどちらかが有効なら、その項目は必須として扱う。時間帯外でも通常の完了操作は可能とし、完了を妨げない。時間帯内で未完了の場合だけ、選択アプリを制限する。既存の必須項目は常時必須として移行し、時間帯指定項目は常時ルールへ混ぜない。

### 4.2 データモデル

TodoとHabitへ同じフィールドを追加する。旧データにこの値がない場合、既存の`isRequired: true`は安全側で`always`に正規化する。既存の集中時間帯を削除する場合は、先に影響項目数と「いつでも必須へ変更される」ことを表示して確認を求める。確認後に最後の割当がなくなった項目だけを`always`へ戻す。

```ts
type RequiredWindowMode = "always" | "scheduled";

type RequiredWindowFields = {
  requiredWindowMode?: RequiredWindowMode;
  requiredScheduleIds?: string[];
};

type Todo = ExistingTodo & RequiredWindowFields;
type Habit = ExistingHabit & RequiredWindowFields;
```

判定関数は`isItemRequiredDuringActiveGate(item, gateConfig, now)`へ集約する。`isRequired`がfalseならfalse、`always`なら常時ルールへ、`scheduled`なら有効なGateScheduleとの積集合が一つでもあればその時間帯ルールへ入れる。Today、遮断、ウィジェット、ネイティブ同期はすべてこの関数を通す。

### 4.3 状態遷移

| 条件 | Today | 選択アプリ | ウィジェット | 完了操作 |
|---|---|---|---|---|
| 必須・常時・未完了 | 「今やる」 | 制限 | 必須バッジ | 完了できる |
| 必須・選択時間帯内・未完了 | 「今やる」＋時間帯 | 制限 | 必須＋時間帯 | 完了できる |
| 必須・選択時間帯外・未完了 | 「この後」＋開始時刻 | 制限しない | 次の時間帯表示 | 完了できる |
| 必須・完了 | 完了表示 | 解除 | 完了表示または非表示 | 復元できる |
| 通常 | 通常一覧 | 影響なし | 通常表示 | 完了・復元できる |

## 5. 遷移と戻る設計

すべてのAndroidネイティブDeep Linkは、Expo Routerが画面パスとして解釈する形式に統一する。Todayは`<scheme>:///`、Todo詳細は`<scheme>:///todos?open=<id>`、習慣詳細は`<scheme>:///habits?open=<id>`とする。Authorityを画面名に使う`<scheme>://today`は使用しない。

| 起点 | タップ箇所 | 遷移先 | 戻る先 |
|---|---|---|---|
| 遮断オーバーレイ | 「Focus Flowで項目を確認する」 | Today | 端末の通常の戻る先 |
| ウィジェット | ヘッダー余白 | Today | ホーム画面 |
| ウィジェット | 行の本文 | 該当Todo／習慣の詳細 | 元のToday相当へ復帰 |
| ウィジェット | 48dpチェック領域 | 完了／復元のみ | 遷移しない |
| Today | 行本文 | 該当Todo／習慣の詳細 | Today |
| Todo／習慣詳細 | 閉じる・戻る | 元の一覧またはToday | 一階層前 |

## 6. 視覚・アクセシビリティ設計

ブランドは「静かな集中と小さな前進」を表す。霧白`#F7F8F5`を基調に、森林緑`#246B5A`を主要操作、深緑`#163E35`を起動画面、若草`#4B9B72`を達成、琥珀`#C98626`を時間帯の注意に使う。色だけに意味を依存させず、時計・鍵・チェックのアイコンと短いラベルを併記する。

| 原則 | 実装基準 |
|---|---|
| 文字 | 本文は標準で15〜16sp相当、補助は11〜12sp相当、行間は1.35倍以上 |
| タップ領域 | 主操作は44dp以上、ウィジェットの完了領域は48dp、本文遷移領域とは重ねない |
| カード | 目的の異なる節だけを分離し、同じ一覧は6dp程度の一定間隔で連続表示する |
| 完了 | 行全体の不透明度を落とさず、明るいグレー背景・十分な文字コントラスト・明瞭な取消線で示す |
| 空状態 | 「次にできること」を1文と1ボタンで示し、専門用語・数値だけの表示を避ける |
| エラー | 原因、影響、次の一手を一つずつ示す。アクセシビリティ未許可時は許可画面への明示ボタンを置く |

## 7. テスト計画と受入基準

| 層 | テスト対象 | 合格基準 |
|---|---|---|
| 単体 | 時間帯の有効判定、日跨ぎ、複数時間帯、既存データ正規化、削除時の安全なフォールバック | Vitestで境界時刻・曜日・完了状態を決定的に検証する |
| プロバイダ | Todo／習慣の作成・更新・完了、集中制限要約、ウィジェット同期 | 時間帯外で解除条件に入らず、時間帯内で未完了なら入る |
| 画面静的回帰 | フォームの必須→時間帯表示、Todayラベル、チェックと詳細の領域分離、起動画面 | 必須文言・状態ラベル・44dp以上の領域が存在する |
| ネイティブ | 遮断画面、ウィジェット、Intent Filter、Deep Link | `scheme:///`、`/todos?open`、`/habits?open`がテンプレートとクリーン生成物に一致する |
| 生成・ビルド | TypeScript、Lint、全Vitest、Androidクリーンprebuild、GitHub Actions署名ビルド | すべて成功。外部認証依存の試験は理由を記録して除外する |
| 実機受入 | Android実機で遮断、ウィジェット、時間帯の内外、Deep Link、戻る、起動、設定 | 下記の手順を全項目通過するまで内部テスト再公開しない |

### Android実機受入手順

1. 集中制限に「平日夜 19:00–21:00」を作り、必須Todoと必須Habitへ割り当てる。
2. 時間帯外では選択アプリが開け、Todayに「19:00から」と表示されることを確認する。
3. 時間帯内では未完了の間だけ選択アプリが遮断され、遮断画面の主ボタンがTodayを開くことを確認する。
4. TodoとHabitを一つずつ完了し、完了後に選択アプリが解除されることを確認する。
5. ウィジェットでチェックを押して完了、再チェックで復元、本文タップで該当詳細、ヘッダー余白でTodayを確認する。
6. 起動直後に全画面導入からTodayへ自然に遷移し、戻る・設定変更・テーマ変更後にも不要な画面が残らないことを確認する。

## 8. 実装順序とレビュー基準

実装は仕様書を作成して終わりにしない。まず本書と既存`design.md`をレビューし、時間帯の意味、データ移行、削除時の挙動、Deep Link形式、実機検証の責任範囲が矛盾しないことを確認する。その後にデータモデル・判定関数・プロバイダ・フォーム・Today・設定・ネイティブ・ウィジェット・起動画面の順に実装する。

レビューで確認する問いは次の三つである。第一に「初めて使う人が時間帯を設定する場所を迷わないか」。第二に「時間帯外でも完了できるという安全な挙動が画面から理解できるか」。第三に「遮断・ウィジェット・アプリ内が同じTodayと項目詳細へ遷移するか」。一つでも満たさない場合は、実装に進む前に設計を修正する。
