# Focus Flow v12 — 全機能・全画面 第2回レビュー記録

## 1. レビュー方法

詳細仕様書、画面実装、状態モデル、Android同期、Widgetテンプレート、既存回帰テストを照合した。確認観点は、目的の明確さ、用語、情報量、誤操作防止、空・失敗状態、戻る、保存・削除、ネイティブ連携、通常版／本人用版の差異である。

## 2. 確認済みの整合

| ID | 対象 | 結果 | 根拠 |
|---|---|---|---|
| OK-01 | Expo所有者 | 設定どおり | `owner: force-flow`は既存のExpoプロジェクト記録と一致する。 |
| OK-02 | IAP依存 | 設定どおり | `expo-iap`プラグインと依存関係がともに登録され、Web非対応時の状態表示も実装されている。 |
| OK-03 | 時間帯必須 | 共通判定を利用 | TodayとAndroid同期が同じ`getGateRuleSummaries`を使い、時間帯中の必須項目を抽出する。 |
| OK-04 | Widget URI | 根本修正済み | `scheme:///`を基点に`appendPath`を使い、4スラッシュURIの余地を除去した。 |
| OK-05 | Widget詳細の終了後 | 修正済み | Todo／習慣フォームを閉じると、Widget起点の場合は明示的にTodayタブへ戻る。 |
| OK-06 | 既存品質ゲート | 通過済み | TypeScript、Lint、Vitest 54成功・1スキップ、通常版・本人用版のクリーンAndroid生成を実行済み。 |

## 3. 改修が必要な指摘

| ID | 対象 | 指摘 | 利用者への影響 | 方針 | 優先度 |
|---|---|---|---|---|---|
| SET-01 | 設定ホーム | 集中制限、見た目、通知、Plusだけが主入口で、データ削除・プライバシー・サポートが小さなテキストリンクに埋もれる。 | 重要なデータ操作や問い合わせ先を探しにくい。 | 「データとプライバシー」を主入口にし、危険操作は設定の最下部に隔離する。 | 高 |
| SET-02 | 集中制限 | 有効化、厳格モード、期限当日、Android許可、診断、対象アプリ、時間帯が一つの長い流れに連続する。 | 初めての人が何から設定すべきか分からず、診断情報を設定必須と誤認しやすい。 | 「1. 有効化」「2. 対象アプリ」「3. 実行時間帯」「困ったとき」の順へ再編し、診断は展開式の確認項目にする。 | 高 |
| SET-03 | 時間帯 | デフォルト名が「日課」で、Todo・習慣の「この時間帯に必ず取り組む」と同じ概念だと分かりにくい。 | 必須項目の時間帯とアプリ制限時間帯の関係を理解しにくい。 | 表示名を「実行時間帯」に統一し、既定名も「時間帯 1」にする。削除時の常時必須フォールバックは維持する。 | 高 |
| SET-04 | 設定の保存感 | テーマ、通知、Widgetの変更は即時保存だが、ユーザーに「保存された」ことが明確に見えない。 | 操作が反映されたか不安になる。 | 値の即時反映を維持し、選択済み状態・短い保存済みフィードバックを統一する。 | 中 |
| SET-05 | データ削除 | プライバシー画面に到達後でないと削除の影響を確認できない。 | 重要操作の所在と影響を理解しにくい。 | 設定ホームのデータ入口で「端末内データ・削除」の意味を短く説明し、実操作は既存の確認モーダルへ限定する。 | 中 |
| UX-01 | 画面遷移 | Widget起点の詳細終了時の戻り先がルーターの暗黙解釈に依存していた。 | Today以外へ戻る可能性があった。 | 明示的なTodayタブ遷移へ変更済み。 | 高・修正済み |
| NATIVE-01 | Widget Deep Link | 4スラッシュURIになり得る生成方式だった。 | 実機でUnmatched Routeになる可能性があった。 | `scheme:///`＋`appendPath`へ変更済み。 | 高・修正済み |

## 4. 画面別レビュー結論

| 範囲 | 結論 | 次の改修／検証 |
|---|---|---|
| Today・Todo・習慣 | 時間帯必須の情報階層とチェック分離は仕様どおり。 | 時間帯前・中・後、日跨ぎの実機確認を行う。 |
| メモ | 空タイトルの一覧表示とTodo化の説明を改善済み。 | キーボードを含む実機入力を確認する。 |
| 振り返り | 現在・次の時間帯の表示を仕様に合わせた。 | 記録なし・週境界で確認する。 |
| その他・法務・サポート | 「その他」への戻り表記を統一した。 | 共有・削除・外部リンクを実機確認する。 |
| 設定 | 主な分かりにくさが残る。 | SET-01〜05を優先改修し、設定単独のテストを追加する。 |
| 遮断・Widget | URI生成・操作分離を修正済み。 | 署名済みビルドで必須実機受入を行う。 |
| 起動・通知・Plus | 状態設計はあるが、OS・ストア依存の最終確認が必要。 | 署名済みAndroidとストアテスターで確認する。 |

## 5. レビュー判定

現時点では、**設定画面の情報設計に高優先度の改修指摘が残るため、再リリース候補には進めない**。SET-01〜05を改修し、設定の導線・保存状態・データ操作・時間帯説明に回帰テストを追加してから、全テストを再実行する。
