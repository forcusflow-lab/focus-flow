# Focus Flow v23 Widget密度・制限アプリ一覧 改修仕様

## 1. 実機フィードバックと判定

v22の実機受入では、必須Pillの形状自体は改善されたが、Pill面が項目行の透過率に追従しないことを確認した。また、候補が5件ある状態でWidgetに3件しか表示されず、Widget下部に大きな未使用領域が残った。回数Habitの`− / 現在値 / +`は行と別部品に見え、アプリ一覧は名称が小さく縦方向の重心が低く、文字サイズ設定の連動不足と操作遅延・不安定さが指摘された。

| 受入ID | v22結果 | v23で解消する状態 |
|---|---|---|
| R01 | 不合格 | 必須Pillの面・文字を、行の透過設定とテーマに一貫して連動させる。 |
| R02 | 不合格 | 大型Widgetでは5件の候補を収め、余白だけが残る3件上限を廃止する。 |
| R03 | 判定不可 | Widget IDごとの全体表示／未完了のみ切替を、候補5件とサイズ変更を含む自動契約で検証する。 |
| R04 | 不合格 | 回数Habitをカード内の連結コントロールへ変更し、行高と操作の重心をそろえる。 |
| R05/R06 | 不合格 | アプリ名を強い主情報として中央寄せに近い垂直配置へ移し、フォント設定と安定した仮想化に接続する。 |

本仕様は利用者の報告本文に基づく。指定により、過去および今回の添付画像ファイルは再閲覧しない。

## 2. Widgetの表示密度とレイアウト

### 2.1 サイズ別の静的行数

静的RemoteViewsのまま、全ての候補をProvider側で安全に割り当てる。既存のsmall/medium/largeへの縮小挙動を維持しながら、実機で余白が生じた大型領域に対応するため、5行用の背の高い表示バケットを追加する。`layout_weight`、0dp、AdapterView、RemoteViewsService、RemoteAdapterは使用しない。

| バケット | 目安の高さ | 最大行数 | 表示目的 |
|---|---:|---:|---|
| small | 149dp未満 | 1 | 最小セルで最重要項目だけを表示する。 |
| medium | 149dp以上250dp未満 | 2 | 標準セルで2項目までを表示する。 |
| large | 250dp以上330dp未満 | 3 | 従来の大型セルで3項目までを表示する。 |
| expanded | 330dp以上 | 5 | 空白を残さず、5件の候補を連続表示する。 |

Android 12以上では4種の`RemoteViews`をSizeF mapへ登録し、pre-Android 12ではwidgetIdごとに現在バケットを保存する。表示候補は`kind:id`単位で重複を除き、未完了表示時は有効必須の未完了項目のみ、全体表示時は完了済みも同じ安定順序で含める。各バケットの上限を超える場合はヘッダーの`ほかn件`で通知する。

### 2.2 必須Pillと透過

必須Pillはテーマごとのprimary-softを基礎にした楕円shapeを使用し、行と同じ`widgetRowOpacity`をalphaとして適用する。Pill文字は完全不透明を保ち、行が0%の場合も背景とのコントラストを損なわない。

### 2.3 回数Habitのカード内操作

回数Habitは行本文に同居する連結コントロールとして表示する。`−`と`+`は等しい視覚幅と明確な背景面、中央の進捗値は独立した読み取り領域にする。コンパクトなWidgetでは過度な高さを増やさず、表示行の高さに縦方向の中心を合わせる。全てのタップ先は行固有のPendingIntentを使い、カード本文の詳細遷移と競合させない。

## 3. 制限アプリ一覧

アプリの表示名を主情報として17sp相当のフォントに上げ、タイルの右側で行の垂直中心に置く。package名は必要な補助情報だけを12sp相当で下に置き、選択状態は右端に固定する。表示設定の文字倍率を`fontScale`へ反映し、タイトル・package名・タイル内先頭文字の比率を連動させる。

| 領域 | 設計 |
|---|---|
| 主名称 | 17sp基準、文字倍率連動、1行省略、行中央近くに配置する。 |
| package名 | 12sp基準、文字倍率連動、長い場合も1行省略する。 |
| 代替タイル | 36dpのテーマ面・先頭文字。名称が空の場合もpackage先頭文字を使う。 |
| 選択操作 | 48dp以上の独立ヒット領域と明確なチェック状態を保つ。 |
| 性能 | `FlatList`、安定key、メモ化行、`renderItem`の安定参照、固定行高・`getItemLayout`、適切な初期/バッチ/window設定を使う。 |

## 4. テスト計画

| 区分 | ケース | 合格条件 |
|---|---|---|
| Widget密度 | 候補0/1/2/3/5/6件、small/medium/large/expanded | 各バケットの行数を使い切り、同一項目の重複も余白だけの3件固定もない。 |
| 必須Pill | 6テーマ×light/dark、行透過0/50/100% | Pill背景が行透過率に一致し、文字は読める。 |
| 回数操作 | count Habitの減算・増算・値表示、完了・詳細タップ | 操作面がカード内で識別でき、各PendingIntentが正しい項目だけを更新する。 |
| 完了済み表示 | 2個のWidget、全体/未完了のみ、サイズ変更、再起動 | widgetId別の状態が保存され、他方のWidgetへ漏れない。 |
| アプリ一覧 | 0/1/100件、日英長名称・package、fontScale3段階、検索/連続選択 | 名称・状態をすぐ判別でき、文字倍率が反映され、スクロールと選択が安定する。 |

## 5. v23 実機受入

| ID | 実機操作 | 合格条件 |
|---|---|---|
| V23-R01 | 5件のToday候補を作り、高さをsmall/medium/large/expandedへ変更する | 1/2/3/5行が用途に応じて表示され、expandedでは空白を残して3件に止まらない。 |
| V23-R02 | 6テーマ×light/darkで行透過を0/50/100%に変更する | 必須Pill・開始・回数操作が行と同じ透過面で表示され、文字とタップ性を保つ。 |
| V23-R03 | 2個のWidgetで全体表示／未完了のみを別々に切替し、サイズ変更・アプリ再起動する | 各Widgetだけに状態が保持され、候補の重複や漏れがない。 |
| V23-R04 | 回数HabitをWidgetから連続で減算・増算し、本文もタップする | `− / 現在値 / +`がカード内で自然に収まり、操作先・詳細遷移が混線しない。 |
| V23-R05 | 多数の制限アプリで検索・選択・テーマ変更・文字サイズ変更を行う | アプリ名・package名・状態が判別でき、文字サイズが連動し、表示と選択が遅延・不安定にならない。 |
