# Focus Flow v12 — 全機能・全画面 詳細仕様・受入基準

## 1. この文書の役割

本書は、Focus Flowの機能を画面単位ではなく**利用者の目的と状態遷移**で定義する詳細仕様である。各項目について、誰が何を達成するか、表示すべき状態、許可する操作、誤操作時の復帰、受入基準を定める。実装・テスト・実機確認は本書にない機能を「対象外」と扱わず、全項目を確認対象とする。

## 2. 横断設計基準

| 基準 | 仕様 |
|---|---|
| 操作の分離 | 完了、詳細、削除、設定変更は別の操作領域に置き、同じタップで複数の意図を実行しない。 |
| 一画面一目的 | 画面の最初に「いま何ができるか」を示し、説明は次の行動に必要な量へ抑える。 |
| 戻る | 画面・モーダルは直前の文脈へ一段階ずつ戻る。遮断画面だけはTodayを明示的な戻り先とする。 |
| 空状態 | 未登録・未選択・未許可の状態には、理由と次の一手を一つだけ示す。 |
| 失敗状態 | 保存、権限、購入、通知、ネイティブ連携の失敗では、原因を断定せず、再試行または安全な代替操作を示す。 |
| 可読性 | 本文は読みやすい行間、十分なコントラスト、縮小しすぎない文字、44dp以上の主要操作領域を基準にする。 |
| 言語 | 日本語を既定とし、言語・文字サイズ・外観は無料で変更できる。 |

## 3. 機能別仕様

### 3.1 Today

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 今日の行動を、優先順位ではなく時間と必須性で迷わず選べるようにする。 |
| 区分 | 「今やる」「この後」「今日のリスト」。時間帯必須が有効中なら「今やる」、開始前なら「この後」、それ以外は今日のリスト。 |
| 操作 | チェックは完了／復元のみ。本文は詳細。明示的な矢印だけが詳細への補助導線。 |
| 空状態 | 今日の項目がなければ、Todoまたは習慣を追加する一つの行動を提示する。 |
| 受入 | 時間帯前・中・後、必須・通常、完了、期限切れの表示が混在しても意味が変わらない。 |

### 3.2 Todo

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 一度きりの行動を、期限・必須性・実行時間とともに記録・完了する。 |
| 作成・編集 | 基本項目を先に置き、必須を選んだ場合だけ「常時」または既存時間帯を選べる。時間帯が未登録なら設定へ誘導する。 |
| 時間管理 | 分数の完了条件がある場合、開始・待機・早期完了を区別し、時間前に通常のチェックで完了しない。 |
| 上限 | 無料上限は未完了のみを数え、完了済みは妨げない。 |
| 受入 | 作成、編集、削除、完了、復元、時間前のロック、時間帯必須、上限到達、戻るを確認する。 |

### 3.3 習慣

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 継続行動を日次・週次の目標とともに記録し、今日の実行可否を明確にする。 |
| 作成・編集 | Todoと同じ必須・時間帯選択を使い、週目標と色は補助項目として扱う。 |
| 完了 | チェックは当日の記録だけを変更し、詳細を開かない。復元時も同じ位置で操作できる。 |
| 受入 | 週目標、時間帯必須、日次完了、復元、色、カードの可読性、戻るを確認する。 |

### 3.4 メモ

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 思いつきをすぐ保存し、必要なものだけTodoへ変換できる。 |
| 表示 | 空タイトルは本文先頭を表示名に使い、空カードに見せない。 |
| 操作 | 作成・編集はキーボードと保存ボタンが重ならない。Todo化は意図が分かるラベルを使う。 |
| 受入 | 空タイトル、長文、キーボード、Todo化、削除、空状態、戻るを確認する。 |

### 3.5 振り返り

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 進捗を責める数値ではなく、次に調整するための短い振り返りとして示す。 |
| 表示 | 現在・次の時間帯、必須進捗、週次傾向を、値がない場合も意味のある文で示す。 |
| 受入 | 記録なし、Todoのみ、習慣のみ、時間帯あり・なし、週の境界で理解可能である。 |

### 3.6 その他・設定

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 日々の行動と分けて、設定、ヘルプ、法務、課金を目的別に探せるようにする。 |
| 表示 | 「その他」は設定とサポートの入口であり、抽象的な管理画面として扱わない。 |
| 設定の分類 | 集中制限、時間帯、表示と言語、Widget、通知、Plus、データとプライバシーを独立した目的に分類する。 |
| 受入 | 各項目について、名称だけで目的が分かり、変更の影響・保存状態・戻る先が確認できる。 |

### 3.7 集中制限・時間帯・厳格モード

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 選んだアプリを、今が対象時間で未完了の必須項目がある時だけ制限する。 |
| 権限 | アクセシビリティの目的、許可方法、許可しない場合の範囲を説明する。 |
| 時間帯 | 時間帯の作成、編集、削除、日跨ぎ、割当済み必須項目への影響を明示する。 |
| 厳格モード | 通常モードとの差と、通常アプリとして制御できないAndroidの境界を明示する。 |
| 受入 | 常時・時間帯前・中・後・日跨ぎ・対象アプリなし・権限なし・厳格モードの状態を確認する。 |

### 3.8 Android遮断画面

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 制限中である理由を伝え、次の行動をTodayに限定して示す。 |
| 主操作 | 「Focus Flowで項目を確認する」は必ずTodayへ遷移し、Unmatched Routeを表示しない。 |
| 再遮断 | 最近使ったアプリ、再起動、既存タスク復帰でも前面検知から再評価する。 |
| 受入 | 通常・厳格モード、時間帯前・中・後、主操作、Android戻る、再開を実機で確認する。 |

### 3.9 Android Widget

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | アプリを開かず、今日のTodo・習慣を確認し、安全に完了／復元する。 |
| 操作分離 | 48dpのチェック領域は完了／復元のみ。行本文は該当詳細。ヘッダー・余白はToday。 |
| 表示 | 必須、時間帯、完了、時間管理ロック、テーマ、背景濃さを一貫して表示する。 |
| URI | 通常版・本人用版ともauthorityを持たない`scheme:///`と`appendPath`で遷移先を作る。 |
| 受入 | 追加、削除、完了、復元、詳細、Today、ロック、透明度、テーマ、長い一覧を実機で確認する。 |

### 3.10 通知

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 任意のリマインダーを、許可と時刻を理解した上で設定できるようにする。 |
| 権限 | 未許可時は理由と許可操作を示す。拒否後も設定を壊さず、再確認できる。 |
| 受入 | 許可、拒否、時刻変更、無効化、テスト通知、OS設定変更後の表示を確認する。 |

### 3.11 Plus・購入・早期完了

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 無料でできることと、任意のPlus拡張を混同させない。 |
| 無料 | Todo・習慣・メモ各2件、制限アプリ5件。言語、外観、文字、Widgetは無料。 |
| Plus | 数の上限解除と名前付きテーマセット。価格・更新・復元・管理はストア画面で確認する。 |
| 早期完了 | 時間管理項目の一回限りの消費型購入として、購読と区別する。 |
| 受入 | 上限、購入、キャンセル、復元、管理、早期完了、オフライン・失敗状態をストア実機で確認する。 |

### 3.12 法務・プライバシー・サポート

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | データ、権限、購入、問い合わせ方法を簡潔で矛盾なく説明する。 |
| データ削除 | 削除対象と取り消せないこと、集中制限への影響を確認モーダルで示す。 |
| サポート | FAQと共有テンプレートに、必要な端末情報だけを含める。 |
| 戻る | 内部画面は「その他へ戻る」、公開ページは対象文書を正しく表示する。 |
| 受入 | 言語、削除、サポート共有、FAQ開閉、法務遷移、戻るを確認する。 |

### 3.13 起動・Deep Link・戻る

| 項目 | 仕様・受入基準 |
|---|---|
| 目的 | 起動、通知、Widget、遮断画面のどこから入っても、迷わず正しい画面へ到達する。 |
| 起動 | ネイティブSplashと全画面導入を深緑基調で連続させ、状態復元後にTodayを示す。 |
| Deep Link | rootはToday、`todos?open=`はTodo詳細、`habits?open=`は習慣詳細へ進む。 |
| 戻る | 直前画面に一段階ずつ戻り、Deep Link起動後にもアプリ終了や不正なタブへ飛ばない。 |
| 受入 | 通常版・本人用版、アプリ停止中・起動中、Widget・遮断・通知経由を実機で確認する。 |

## 4. 共通受入判定

各機能は、次の条件を満たすまで合格にしない。第一に、仕様と状態遷移に矛盾がないこと。第二に、最初の画面から目的・主操作・次の結果が理解できること。第三に、空・読み込み・権限なし・上限・失敗・戻るを安全に処理すること。第四に、対応する自動テスト、Androidクリーン生成、署名ビルド、必要な実機項目を通過すること。
