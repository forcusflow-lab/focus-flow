# Focus Flow v17 / 本人用v7 Widget行同一性・密度是正仕様

**記録日:** 2026-08-26  
**起点:** 本人用v6実機で、Widget自体は追加できたが、Todo 1件が2行に表示され、上段のチェック操作後に下段だけが完了状態となった。加えて、視覚チェックが過大で、文字切れと低い可読性が確認された。

## 1. 不具合の再現仕様

| ID | 事前条件 | 実機操作 | 期待結果 | v6実際結果 |
|---|---|---|---|---|
| R-01 | 未完了Todoが1件だけ | アプリ同期後にWidgetを見る | 表示行は1件だけ | 同じTodoが2行に重複表示された |
| R-02 | R-01のWidget | 1行目のチェックを押す | 1行目だけが完了表示へ変わる | 2行目だけにチェックが移動した |
| R-03 | Todo／習慣が短文・長文、必須・通常で混在 | 小・中Widgetを表示する | タイトル、補足、必須、チェックを判読できる | チェックが過大で、文字切れ・視認性低下がある |

## 2. 原因仮説と設計判断

v6の状態配列は、Todo／習慣の入力データから一意性を保証せずに静的2行へ切り出していた。また、Android側の完了処理は一致するIDを末尾まで走査して対象を上書きするため、同じ`id + kind`が複数行に入ると後の行だけを更新し得る。この二つの経路を、重複表示とチェック移動の共通原因として扱う。

さらにv6では、48dpのタップ領域そのものにチェック背景を設定していた。タップ領域は維持しつつ、視覚的なチェックボックスを20dpの内側Viewへ分ける必要がある。

## 3. v7の状態・行同一性契約

> Widgetへ渡す各行は、`kind:id`を一意キーとする。状態生成時とProvider描画時の両方で重複を除外し、同じキーを2行へ描画してはならない。

| 層 | 要件 |
|---|---|
| JS状態生成 | `kind:id`で安定順を保った重複除外を行い、最大2件をProviderへ渡す前に保証する |
| Provider描画 | `kind:id`で再度重複を除外し、空行の全View・PendingIntentを明示的にリセットする |
| 完了／復元 | 対象キーが配列に1件だけであることを確認し、複数一致時は操作せずWidgetを更新しない |
| PendingIntent | `widgetId + row + operation + kind + itemId`をdata URIとrequestCodeへ含め、行ごとのIntentを区別する |
| 行UI | 高さ48dp、操作領域48dp、視覚チェック20dp、タイトル1行、補足は必要時だけ10sp、本文は残余幅を確保する |

## 4. v7の受入基準

| ID | 判定内容 | 合格条件 |
|---|---|---|
| A-01 | 1件データの表示 | Todoまたは習慣が1件なら、Widgetも1行だけを表示する |
| A-02 | 2件データの表示 | 異なる`kind:id`だけを上から2行表示し、同一キーの重複はない |
| A-03 | 完了／復元 | 上段・下段をそれぞれ操作しても、押した行以外の状態・本文・補足は変わらない |
| A-04 | 詳細・Today | 本文は該当詳細、チェックは該当項目の完了／復元、ヘッダーと空状態はTodayのみを開く |
| A-05 | デザイン | 20dp視覚チェック、48dpタップ領域、1行タイトル、必要時の補足、ライト／ダークの高コントラストを維持し、文字切れ・重なりがない |

## 5. 必須テスト

状態生成、Provider描画、完了／復元の各層について、同一Todoが重複入力された場合、Todoと習慣で同じUUID風文字列を持つ場合、1件だけの場合、2件ある場合、完了表示が`dim`と`hide`の場合を検証する。署名APKのManifest、package、versionCode、署名、静的layoutを再検証した後、実機でA-01からA-05を順番に受入する。

## 6. 実装後レビューと自動検証

v7では、JS状態生成に`uniqueWidgetItems()`を導入して安定順の`kind:id`重複除外を行い、Providerでも`uniqueStaticItems()`により同じ防御を行う。完了・復元は対象一致数が1件の場合だけ処理し、複数一致時に末尾行を更新するv6の挙動を禁止した。行のPendingIntentには`widgetId + row + operation + kind + itemId`を含めたdata URIとrequestCodeを設定する。

チェック操作は48dpの外側FrameLayout、20dpの内側ImageViewへ分離した。本文は12sp、補足は10sp、タイトルは1行、省略表示、補足は必要時だけ表示する。v6で見られた48dp全体を塗るチェック背景は使わない。
