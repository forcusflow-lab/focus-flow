# Focus Flow 公開・収益化準備監査

**基準日：2026年8月15日。** 本書は、現在のFocus Flowコード、公開資料、Google Play公式ガイダンスを照合した実行用の監査記録です。これは法的助言ではありません。プライバシーポリシー、販売条件、税務、発行主体の表示は、公開地域に応じて適格な専門家へ確認します。

## 結論

Focus Flowは、ローカル保存のTodo・習慣・日課と、任意のAndroidアクセシビリティサービスによるアプリ制限という差別化された中核体験を備えています。一方で、**現時点ではクローズドベータとして扱い、決済を開始しない**ことが安全です。理由は、実機での制限機能確認、正式な発行主体・サポート連絡先、公開済みプライバシーポリシー、Play Console上のAccessibilityService申告とData safety申告、実課金の購入・復元・失効テストが残っているためです。

| 領域 | 現状 | 今回リポジトリ内で完了する作業 | 外部で完了する作業 |
| --- | --- | --- | --- |
| コア品質 | Todo、習慣、日課、サブタスク、Android制限、安全停止、オンボーディングを実装済み | データ削除、公開向けコピー、設定・サポート導線、検査を強化 | 複数の実機・OS・メーカーでの手動確認 |
| アクセシビリティ | 任意利用、明示説明、設定導線、安全停止を実装済み | 申告用の説明・撮影台本を更新 | Play Consoleの宣誓とデモ動画の提出 |
| プライバシー | 端末内保存、広告・行動追跡なしという設計とドラフトを保有 | アプリ内の削除操作とポリシー整合を追加 | 発行主体名、サポートメール、HTTPS公開URLの確定 |
| 課金 | Plusの候補と価格仮説はあるが、購入機能は未提供 | 価格・価値境界・復元/失効要件を公開資料に確定 | 商品ID、価格、課税、販売国、ライセンステスター、Play Billingの実課金検証 |

## Google Play要件との照合

Focus FlowはAccessibilityServiceを**アクセシビリティ支援ツールとしては宣言しない**前提で、ユーザー自身が選んだアプリが前面に来たことを検知し、あらかじめ定義された制限ルールを適用します。Google Playでは、この用途にアプリ内での独立した目立つ開示、明確な利用目的、肯定的な同意操作、AccessibilityService申告が求められます。[1] 現在の初回案内と設定内モーダルはこの方向に沿っていますが、公開審査では、開示・同意・設定・機能利用・同意しない場合の再表示まで確認できる動画または明確なレビュー手順が必要です。

Data safetyは、クローズドテストを含む公開トラックで必要であり、データを収集しない場合もプライバシーポリシーURLと申告が必要です。[2] 署名済みAABに含まれる全SDKと、実際に作動するネイティブ実装を基準に最終申告します。現在のコードレビュー上では、Todo本文、習慣、メモ、日課、表示設定は端末内に保存され、アプリ内広告・行動追跡SDKを使用していません。ただし、この評価は**最終ビルドのSDK監査・通信確認を置き換えません**。

Google Playでデジタル機能・定期購入を販売する場合、Plus権利はPlayの購入結果に基づき、成功後に確認・付与・承認される必要があります。定期購入の有効状態は、復元、保留、キャンセル、失効にも対応させ、利用者がサブスクリプションを管理できる導線をアプリ内に置きます。[3] 現在はこの実課金経路が存在しないため、購入ボタン、価格の確約、Plusロックの表示は公開しません。

## 今回実行する改善

1. **信頼とデータ制御**：ユーザーがアプリ内データを一括削除できる確認付き操作を追加し、削除するとAndroidの制限設定も無効化されるようにします。プライバシー画面と公開ポリシーの削除説明を一致させます。
2. **公開版の情報設計**：ベータ限定の文言を、公開後も正確に成り立つローカルファースト・安全停止・サポート中心の表現へ改めます。収益化は、実課金が接続されるまで「準備中」と明確にし、誤解を招く擬似購入導線は置きません。
3. **商品化の境界**：無料版は日々の計画と安全な1つの制限ルール・1つの選択対象アプリを維持し、Plus候補は複数ルール、複数制限アプリ、拡張テンプレート、詳細な振り返りに限定します。中核の安全停止や解除条件を有料化しません。
4. **ストア運用資産**：Google Playのプレビュー素材要件に沿って、公開用のfeature graphicと5画面のスクリーンショット撮影計画を整えます。プレビュー素材はテストトラックにも表示されるため、公開前の内容と主張を揃えます。[4]
5. **リリースガード**：versionCode、AAB、ネイティブ生成、静的検査、公開ソース監査を再実行し、ビルドできる状態を確認します。実機確認とConsole作業は、完了条件・停止条件を明示して引き渡します。

## 課金開始の判定ゲート

次の全条件が満たされるまでは、クローズドベータを無料で運用します。

| 判定ゲート | 合格条件 |
| --- | --- |
| P0安全性 | 誤制限、復帰不能、制限ループが未解決でない。安全停止が実機で確認済み。 |
| 端末互換性 | 少なくとも異なるメーカー・Androidバージョンを含む実機で、設定・制限・解除・日課・ウィジェットを確認済み。 |
| 公開情報 | 発行主体、監視するサポートメール、プライバシーポリシーURL、Data safety、AccessibilityService申告が最終ビルドと一致。 |
| 購入基盤 | Play Consoleに商品とベースプランを作成し、ライセンステスターで購入・保留・復元・キャンセル・失効を確認済み。 |
| 価値検証 | 継続利用、初回セットアップ完了、制限機能の成功率、サポート負荷を確認し、Plusの価値が中核体験を損なわない。 |

## 外部でしか完了できない最終項目

次の項目は、発行主体またはテスターの実機・アカウント情報が必要なため、本リポジトリからは実行できません。

| 外部作業 | 実行者 | 完了の証跡 |
| --- | --- | --- |
| Play Console開発者アカウントの本人確認・支払いプロファイル | 発行主体 | Consoleの有効な開発者アカウント |
| 発行主体名・サポートメール・プライバシーポリシーURLの確定 | 発行主体 | 公開HTTPS URLと監視可能なメール受信箱 |
| AccessibilityServiceの申告・審査用動画 | 発行主体 | Console提出内容と実機録画 |
| Data safety・コンテンツレーティング・販売国・カテゴリ | 発行主体 | Console提出済みフォーム |
| クローズドテスト・端末マトリクス・プレローンチレポート | テスターと発行主体 | テスト結果、障害記録、停止判断 |
| Plusの商品作成・税務設定・実課金テスト | 発行主体 | 商品ID、ライセンステスターの結果、購入フロー記録 |
