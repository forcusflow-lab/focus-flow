# Focus Flow v13 — 高密度Widget・ダークモード 設計レビュー

## 1. 結論

実機で報告された問題は、単一の余白値ではなく、**Widgetをカードの集合として扱った構造**と、**アプリの表示設定からネイティブWidgetへの文字サイズ同期が欠けていたこと**、さらに**全画面でライト専用の固定色と動的パレットが混在していたこと**による。前回の「可変行高」への変更は、短文のWidget行で余白を増やし、一覧性を下げたため採用しない。

Android公式は、Widgetを複数サイズで利用されるレスポンシブな面として設計し、領域を有効に使い、ライト・ダークテーマとコントラストへ適応させるよう案内している。[1] Collection Widgetは垂直スクロールする同種リストに適し、行ごとの操作はfill-in Intentで分けられる。[2] このためFocus Flowは、カード集合ではなく単一のリスト面、48dp操作領域、明確な行本文を基本とする。

## 2. 根本原因

| 対象 | 確認結果 | 問題 | 是正判断 |
|---|---|---|---|
| Widget行 | 最小68dp、上下各10dp、最大2行タイトル、補足行、個別背景Drawableを使用していた。 | 短いTodoでも行が大きく、カードのように見え、少数表示になる。 | 標準48dpの単一行を基準にし、補足は必要時のみ小さい第2行、行間は1dpの区切り線にする。 |
| Widget本体 | 12dp外側余白、42dp見出し、8dpリスト間隔を予約していた。 | 最小サイズで一覧領域が不足し、残余が不自然に見える。 | 外側余白を10dp未満、見出しをコンパクト化し、リストへ残余高を渡す。 |
| チェック | 48dp操作領域はあるが、カード高と補足の増減で視覚中心が変化する。 | 見た目のチェック位置が本文の中心と揃わない。 | 行を基準高に固定し、チェックを`gravity=center`で単一行の垂直中心へ固定する。 |
| Widget文字サイズ | ネイティブ側はWidget専用サイズを読むが、JS同期状態にその値が含まれない。 | アプリの文字サイズとWidgetが連動せず、設定変更の結果を予測できない。 | `displaySettings.fontScale`をWidget状態へ明示送信し、Todo・習慣で共通の係数と行高に使う。 |
| Widget配色 | 行の背景Drawableと完了色に固定色が残る。 | アプリテーマがdarkでも行の面・本文・補足・境界の意味が揃わない。 | パレットのsurface/elevated/text/muted/border/primaryだけを行描画へ渡す。 |
| 共通UI | `COLORS`がライト用の固定色を返し、各画面のStyleSheetにも白面・暗い本文・淡い補足色が残る。 | dark時に背景だけ変わり、本文・補足・入力・境界が読みづらくなる。 | 共通パレットフックと意味色を導入し、画面・モーダル・空状態・入力をライト／ダークのペアで上書きする。 |

## 3. 設計の採否

| 判断 | 採用・不採用 | 理由 |
|---|---|---|
| 項目ごとのカード背景 | 不採用 | 1件だけでも大きな塊となり、ホーム画面で必要な一覧性を損なう。 |
| 固定56dp／68dpの行 | 不採用 | 実機で短文の密度を下げた。 |
| 48dpのチェック操作領域 | 採用 | 誤タップを避けつつ、本文Deep Linkと明確に分離できる。 |
| 標準48dpの行と1行タイトル | 採用 | 小Widgetで複数項目を見せる基準として十分であり、長文は詳細画面へ委ねられる。 |
| 必須の専用カード・空予約 | 不採用 | 意味を示すために一覧密度を失うため、アクセント線と短い補足へ移す。 |
| Widget専用の独立文字サイズ | 不採用 | ユーザーがアプリの文字サイズを変えた時の予測可能性を下げる。アプリ設定へ従属させる。 |
| 固定ライト色の継続利用 | 不採用 | Android公式が挙げるダークテーマの典型的な可読性問題に該当する。[3] |

## 4. 全画面監査の優先度

最優先は、Widget、共通UI、Today、Todo、習慣、メモ、設定、Plus、法務・プライバシー・サポートのカード・本文・補足・入力・モーダルである。次に、振り返り、その他、起動、遮断、通知、空・読み込み・エラーを対象にする。すべての画面は、通常、空、長文、無効、完了、モーダル、戻るの状態をライト・ダークで確認する。

## 5. 修正後の合格条件

1. 標準サイズのWidgetで、見出しの下に48dp基準の項目を2件以上表示できる。
2. Todo・習慣のタイトル、補足、チェック位置は同じサイズ規則を使い、アプリ文字サイズの三段階に連動する。
3. チェック、本文、ヘッダー／余白のタップ結果が混ざらない。
4. ライト・ダークの全画面・全状態で、本文、補足、入力、境界、主要・補助ボタン、完了・無効・エラーが識別できる。
5. 自動回帰、通常版・本人用版のAndroid生成、署名ビルドを通過し、実機受入で確認する。
