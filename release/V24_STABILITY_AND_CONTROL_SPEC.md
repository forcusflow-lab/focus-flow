# Focus Flow v24 安定性・操作面・設定UI仕様

## 1. 実機フィードバックと優先度

v23実機受入では、Widgetの必須Pill透過、候補5件の表示密度、Widget別の完了済み表示は合格した。一方、回数Habitの`− / 進捗 / +`は進捗値より下へずれて視認しにくく、記号単独では押せる範囲を判断しにくい。制限アプリ一覧は検索面だけが角丸で行と統一されず、行の外形が小さく、現状の文字密度は再調整を要する。

加えて、透過率スライダーのドラッグが段階的に見え、指の位置と表示値がずれる、0%より左側へ見かけ上動くという報告があった。さらに、データが消える、他アプリ利用中にFocus Gateがちらつく、Todo入力後の詳細導線が遅れるという機能上の問題を最優先で扱う。本仕様は利用者の報告本文を根拠とし、指定により添付画像ファイルを再閲覧しない。

| 優先度 | 受入ID | 課題 | v24の判定基準 |
|---|---|---|---|
| P0 | V24-R01 | データが不意に消える | 読込・同期・保存失敗で既存データを空配列へ置換せず、再起動・バックグラウンド復帰・Widget操作後も状態を保持する。 |
| P0 | V24-R02 | 他アプリ中にFocus Gateがちらつく | 制限対象かつ制限が有効な場合だけ、重複起動をせず、意図しないOverlay/Activityの連続介入を起こさない。 |
| P1 | V24-R03 | 回数操作の視認性と押しやすさ | `減らす`・進捗値・`増やす`を同一高さのラベル付きボタンとして行の中心へ揃え、本文タップと混線しない。 |
| P1 | V24-R04 | 制限アプリ一覧・検索の統一感 | 検索面とアプリ行を同じフラット外形・境界へ統一し、行をコンパクト化して文字倍率にも追従する。 |

| P1 | V24-R07 | Todo詳細遷移の遅延 | 入力カードを押した操作からシート/詳細表示まで、同期I/Oや重い再描画で1テンポ待たせない。 |

## 2. 設計

### 2.1 Widget回数Habit操作

回数Habitの行の右端は、独立した三分割カードとして扱う。左端は`−`ではなく`減らす`、中央は読み取り専用の`現在値 / 目標`、右端は`増やす`とし、3面の高さ・中央揃え・テーマ・行透過を統一する。コンパクトなWidgetでは明確な文言を保つために、左右ボタンは短い日本語ラベルを採用し、最低44dpのタップ範囲を確保する。各操作は固有のPendingIntentを維持し、本文領域の詳細遷移とは重ならない。

### 2.2 必須Pill

楕円Pillは既存の行透過連動を維持し、テーマのprimaryを基準にした1dpのstrokeを追加する。枠線だけを完全不透明にせず、背景と同じ透過段階の資産を使って、行面から唐突に浮かない設計とする。

### 2.3 制限アプリ一覧と検索

検索枠を独立した丸い入力ボックスにせず、アプリ行と同じフラットな四隅・border・surfaceトークンで表現する。アプリ行は余分な上下余白を抑えつつ、表示名を15sp基準、package名を11sp基準とし、`fontScale`で比例させる。表示名ブロックは行の垂直中央に寄せ、長い名称・package名はそれぞれ1行で省略する。`FlatList`の安定key、固定高さ、メモ化行、安定したrender callbackを保ち、検索文字列変更時の不要な全一覧再生成を避ける。

### 2.4 透過率スライダー

スライダーはコンテナの実測幅、左右thumb半径、タップ座標を一つの変換関数で扱う。値は`clamp(round(position * 100), 0, 100)`で決定し、表示値・thumb位置・保存値を同じ整数値から描画する。ドラッグ中は画面内のローカルstateだけを更新し、永続化とNative同期はジェスチャー終了時の一回に限定する。これにより、動きの連続性とI/O頻度を両立する。

### 2.5 データ保存とFocus Gate

AsyncStorageの読込例外、JSON不正、部分同期失敗は、既存のメモリ状態または直近の検証済みスナップショットを保持し、空データを保存して上書きしない。Widget操作のqueue消費は冪等にし、処理済み操作を再実行しない。

Focus Gateは、利用中アプリのpackageが制限対象で、かつ現在時刻が有効な制限時間帯に一致するときだけ表示する。同一package・同一セッション中の多重起動は抑止し、Overlay/Activityの表示が成功した直後にすぐ再発火しないデバウンスを設ける。Focus Flow自身、システムUI、制限外アプリは介入対象にしない。

### 2.6 Todo詳細導線

Todo入力の本文タップでは、同期保存やWidget同期を開始する前にナビゲーション/シート開閉を実行する。フォームの初期値・派生データはメモ化し、表示直後の全件集計・Native同期・レイアウト測定を避ける。

## 3. 自動テスト計画

| 区分 | ケース | 合格条件 |
|---|---|---|
| 保存 | 正常読込、JSON破損、読み込み拒否、空データ、Widget queue再送 | 既存データが空で上書きされず、失敗状態を安全に扱う。 |
| Gate | 制限外/自アプリ/制限内/時間帯外/連続イベント | 必要な一回だけ表示し、制限外では表示しない。 |
| 回数操作 | `減らす`/`増やす`、進捗、固有ID、本文タップ | ラベル・同一高さ・固有Intent・境界を確認する。 |
| 一覧 | 0/1/100件、検索、長い名称、fontScale3段階 | 検索面と行が同じ外形で、文字とリスト性能契約が成立する。 |
| Slider | 0/1/50/99/100%、領域外、tap/drag/end | 値が0〜100にclampされ、表示値と保存値が一致する。 |
| Todo導線 | 詳細開閉・フォーム初期化・Widget同期 | 表示前に重い保存/同期を開始しない。 |

## 4. リリース前の実機受入

v24本人用APKで、V24-R01〜R07を端末上で個別に判定する。R01〜R02はデータ安全性と他アプリ利用に関わるため、画面上の見た目だけでなく、アプリ再起動・バックグラウンド復帰・複数回の対象アプリ起動を含める。全項目の実機受入前は、本人用APKを正式版およびGoogle Play版として扱わない。

## 5. 実装・自動検証結果

AsyncStorage更新を順序保証キューに集約し、読込失敗時に既存状態を空データで上書きしない。Focus Gateは前面が同じ制限対象または一過性システムUIのときだけ遅延イベントを再遮断し、制限外アプリへ介入しない。透過率は0〜100%・1%単位でローカル座標から計算し、ドラッグ終了時のみ永続設定へ反映する。Widget回数Habitはテーマと透過に追従する独立ボタン面と読み上げ説明を持つ。制限一覧はフラット検索、コンパクト行、文字サイズ・フォント設定の連動へ更新した。Todoフォームは描画前に初期値を設定する。
