# Focus Flow v14 プロダクト品質PDCA計画

## 目的

v13実機で判明した時間型Habitの不整合、チェック操作の詳細遷移、Widgetと本体の視覚階層差を是正する。同時に、Todo・Habit・Today・メモ・集中制限・設定・Widget・戻る・Deep Link・空／読み込み／エラー状態を対象に、一般的なモバイル生産性アプリの操作原則と比較した監査を実施する。

## 比較レビューの結論

| 比較対象 | 公式資料から確認した原則 | Focus Flowへ反映する基準 |
|---|---|---|
| Todoist | Widgetでは、タスク本文は詳細を開き、行頭の円形完了操作は完了だけを行う。compact modeでは操作を減らして可読性と表示件数を優先する。[1] | タップ領域を明確に分離し、チェック操作が詳細遷移に流れないようにする。Widgetの小サイズでは操作を詰め込まない。 |
| Microsoft To Do | WidgetはMy Dayの既存項目を読みやすく表示し、リスト名からアプリ内の対応リストを開く。[2] | WidgetはTodayの要約と項目一覧に絞り、見出し・本文・完了操作の目的を混在させない。 |
| TickTick | Habitは「一回で完了」「固定量」「手動量」を分け、目標に対応したチェックイン方式を選ぶ。Today HabitsとWeekly HabitsのWidgetを分離して進捗を扱う。[3] [4] | `check`、`count`、`minutes`を別状態機械として扱う。`minutes`に±を流用せず、開始／経過／目標到達の表示を採用する。 |
| Habitify | 時刻で整理された習慣と、集中用の内蔵タイマーを提供し、実行と記録を混同しない。[5] | 時間型Habitは「計測を開始する」と「目標を満たして完了する」を分離する。未開始・計測中・一時停止・達成済みを文言と色だけに頼らず表示する。 |

## 改訂する非交渉の操作仕様

| 種別 | 行頭操作 | 本文タップ | 進捗操作 | 完了条件 |
|---|---|---|---|---|
| Todo | 直ちに完了／復元のみ | 詳細を開く | なし | チェック1回 |
| `check` Habit | 直ちに完了／復元のみ | 詳細を開く | なし | 今日のチェック1回 |
| `count` Habit | 目標達成済みのみ完了／復元 | 詳細を開く | ±で数値を変更 | `progressValue >= targetValue` |
| `minutes` Habit | 目標達成済みのみ完了／復元 | 詳細を開く | 開始後、実時間で経過を表示する。数値±は表示しない | 計測時間が目標以上 |

> 時間型Habitのロック表示は「操作不能」の記号で終わらせない。未開始なら開始、計測中なら経過、達成後なら完了という次の状態を必ず明示する。

## Widgetの改訂方向

Widgetは単一のフラットなTodayカードとして扱い、カード内にさらに浮いたカードを重ねない。surface、角丸、区切り、本文サイズ、必須Pillは本体Todayのトークンに対応させる。小サイズでは行頭チェックとタイトルだけ、中サイズでは必須Pillまたは進捗を追加、大サイズで時間型Habitの開始／一時停止と経過を表示する。小サイズに全操作を詰め込まない。

## 監査対象と受入基準

| 領域 | 状態 | 主な確認項目 |
|---|---|---|
| Today / Todo / Habit | 空、通常、必須、完了、時間待機、時間計測中、長文、文字サイズ3段階 | クリック先、完了条件、Pill切れ、カード密度、コントラスト |
| Widget | 小・中・大、Todo、3種Habit、必須、完了、ライト／ダーク、透過 | 1/2/3行、操作の意味、誤タップ、同期後サイズ維持、情報の省略順 |
| メモ / 振り返り / その他 | 空、入力中、保存済み、削除確認 | キーボード干渉、戻る、保存・削除の復帰 |
| 集中制限 / 設定 / Plus / 法務 | 有効／無効、権限拒否、課金非対応、外部リンク失敗 | 説明量、戻る先、失敗理由、行動可能な次手 |
| 起動 / Deep Link / 通知 | 初回、復帰、対象あり／なし | Today復帰、該当詳細、未一致URLの安全な復帰 |

## PDCAの出荷ゲート

1. **Plan**: 画面・操作・状態・受入基準をこの文書とテストへ反映する。
2. **Do**: 状態機械とタップ領域を修正し、Widgetを時間型Habitの表示優先度から再構成する。
3. **Check**: 単体、統合、静的Widget契約、通常／本人用クリーン生成、署名APK、実機画面を確認する。
4. **Act**: 失敗時は該当の再現条件・テストを先に追加し、修正後に全回帰を行う。未受入の成果物はGoogle Playへ配布しない。

## P0コード監査の結果

| 領域 | 観測した根本原因 | 判定 | 是正方針 |
|---|---|---|---|
| Habitタブ | `progressUnit === "minutes"`でも、`habitProgressLabel`が真の場合に回数型と同じ±コントロールを描画する | 不合格 | `minutes`専用の開始／計測中／達成表示と開始操作に分岐する |
| Today Habit | Habitタブと同じ汎用±コントロールを再実装している | 不合格 | 共通時間型コントロールを使用し、別実装をなくす |
| 時間計測状態 | 永続化される開始時刻はあるが、画面は`dailyProgress`を表示するため、経過していても`0/30分`のまま見える | 不合格 | 開始時刻から秒単位の経過・残りを導出し、計測中表示を1秒単位で更新する |
| 本体チェック | チェック領域と詳細領域の意図は分かれているが、時間型Habitでは「開始」と「完了」の意味が同じチェックへ混在している | 不合格 | 時間型は行頭チェックを完了状態のみに限定し、開始専用ボタンへ分離する。行頭のタッチ領域を前面化する |
| Widget | 全サイズバケットで`showControls = false`のため、時間型の開始／計測中分岐は到達不能。未達成はロックアイコンだけになる | 不合格 | 中・大サイズで時間型の専用開始／計測中ラベルを表示し、ロックだけの状態を廃止する |
| Widget完了領域 | 完了不可の行頭操作がToday遷移へフォールバックする | 不合格 | 完了不可の操作には無害なno-opを設定し、行頭から詳細・Todayを開かない |

## v14 実機受入条件

| ID | 操作 | 合格条件 |
|---|---|---|
| V14-R01 | 30分の時間型Habitで`開始`を押し、1分以上待つ | ±ではなく`計測中`と実経過時間が表示され、画面を切り替えても経過が保持される。 |
| V14-R02 | 目標時間前の行頭チェックを押す | 詳細を開かず、完了にもならず、開始操作だけが計測を開始する。 |
| V14-R03 | Todo・`check` Habit・`count` Habitの行頭チェックを押す | 対象だけが完了／復元し、詳細画面へ遷移しない。 |
| V14-R04 | Widgetの中・大サイズで時間型Habitを表示し、`開始`を押す | ロック記号だけで終わらず、`開始`→`計測中`へ切り替わる。アプリ起動後にも同じ開始時刻で表示される。 |
| V14-R05 | Widgetを小・中・大、ライト／ダークで表示 | 1/2/3行、フラットな単一カード、必須Pill、チェック、開始ボタンが判読できる。 |
