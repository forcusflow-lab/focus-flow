# Focus Flow v15 時間型Habit・Widgetカード改訂仕様

## 改訂の背景

v14実機では、時間型Habitが`計測中`のまま停止できず、行頭チェックも設定時間より前には手動完了できなかった。またWidgetでは、必須Pillがタイトルの下にあり、時間型Habitの操作だけが角張った独立部品として浮いて見えた。v15では**計測の記録**と**今日の完了**を別状態として扱い、全てのHabitで行頭チェックによる完了／復元を可能にする。

Habitifyはタイマー中の一時停止・再開と、途中停止時の経過時間保存を案内している。[1] TickTickも固定量・手動量・一回完了を別の記録方式として扱う。[2] この二つの原則を踏まえ、Focus Flowは進捗計測を残しつつ、ユーザーが一日のHabitを手動記録できる設計にする。

## 時間型Habitの状態機械

| 状態 | 永続データ | 行頭チェック | 専用操作 | 表示 |
|---|---|---|---|---|
| 未開始 | 開始時刻・停止経過ともになし | 直ちに手動完了 | `開始` | `00:00 / 30:00` |
| 計測中 | 開始時刻と停止済み秒数 | 直ちに手動完了 | `一時停止` | `計測中`と実経過時間 |
| 一時停止 | 停止済み秒数、開始時刻なし | 直ちに手動完了 | `再開` | `一時停止`と保存済み経過時間 |
| 目標到達 | 経過時間が目標以上 | 完了／復元 | なし | `達成` |
| 手動完了 | `completedDates`に当日を保存 | 復元 | なし | `完了` |

手動完了は目標時間の代替ではなく、その日のHabit達成を記録する操作である。復元すると当日の完了フラグと計測状態を初期化し、誤って記録した場合にも一貫してやり直せる。

## Widgetレイアウト仕様

Widgetは一つのTodayコンテナに、**区別可能な薄いmini-card行**を積む。複数の重い浮遊カードではなく、同じsurface・角丸・余白の反復で、TodoとHabitを一目で区別できるようにする。

| 要素 | v15仕様 |
|---|---|
| 行の区別 | 各行に浅いborder・4dpの間隔・kind別の細いアクセントレールを適用する。 |
| 必須 | タイトルと同じ先頭行で、`必須`Pill→タイトルの順に置く。非必須には空の代替Pillを置かない。 |
| Todo / Habit | Todoは小さな`Todo`補足、Habitは週次または進捗補足を表示し、kindを文言だけに依存しない。 |
| 時間型Habit | メタ行に`計測中 00:31 / 30:00`または`一時停止 00:31 / 30:00`を表示し、末尾の同じ角丸インライン操作を`開始`／`停止`／`再開`へ変える。 |
| 行頭チェック | 全Habitで完了／復元専用。計測操作や詳細遷移に使わない。 |
| サイズ対応 | 小／中／大の1/2/3行を維持し、mini-cardの余白だけを省略する。リサイズ判定と操作の一意性はv13契約を維持する。 |

## 受入基準

| ID | 操作 | 合格条件 |
|---|---|---|
| V15-R01 | 時間型Habitを開始し、停止、再開する | 経過時間が停止中に増えず、再開後は保存値から増える。画面切替・アプリ復帰後も維持される。 |
| V15-R02 | 未開始・計測中・一時停止の時間型Habitで行頭チェックを押す | 予定時間前でも対象だけが完了／復元し、詳細を開かない。 |
| V15-R03 | Widgetで時間型Habitを開始・停止・再開する | 本体と同じ経過・状態へ同期し、操作がToday遷移にならない。 |
| V15-R04 | 必須Todo／HabitをWidgetで表示する | `必須`がタイトルの先頭に完全表示され、非必須の行にはPillがない。 |
| V15-R05 | Widgetを小／中／大、ライト／ダークで確認する | TodoとHabitのmini-cardが区別でき、行間・Pill・本文・計測操作に過剰な余白・重なり・低コントラストがない。 |

## 実装・レビュー結果

| 領域 | v15で実装したこと | 自動レビュー結果 | 実機で残る確認 |
|---|---|---|---|
| タイマー状態 | 開始時刻と停止済み秒数を別保存し、`開始`・`一時停止`・`再開`を同じ共通コントロールで扱う。 | 実時間、停止値固定、再開、日付別保存の契約を追加。 | V15-R01 |
| Habit完了 | 行頭チェックで時間目標前でも手動完了／復元できる。時間は進捗情報として保持する。 | 手動完了は`completedDates`だけで判定し、時間到達だけで完了にしない契約を追加。 | V15-R02 |
| 画面遷移 | チェックの44dp操作領域を本文・詳細操作から分離する。 | Todo・Habit・Todayの`onPressIn`遮断と専用`onToggle`を確認。 | V15-R02 |
| Widget | 全Habitを手動完了可能とし、時間型は開始／停止を操作キューに保存する。 | `timer_pause`、経過秒、開始時刻、操作一意性、RemoteViews安全構造を確認。 | V15-R03 |
| Widget視覚 | 40dpヘッダーの下へ、54dp・12dp角丸・3dp間隔の個別mini-cardを最大3行表示する。必須Pillはタイトル先頭に置く。 | light/dark・必須／完了・開始／停止drawableを契約化。 | V15-R04、V15-R05 |
| 全画面監査 | Today、Todo、Habit、Memo、Insights、More、Settings、集中制限、Plus、法務、Support、起動、Deep Link、Widget、空／エラー状態を対象にした既存画面契約を回帰対象とした。 | 26ファイル・79テスト合格、TypeScript・Lint合格。P0は実機再受入、P1は既存の画面別契約を維持。 | P0を優先 |

> 実機での視覚・ネイティブ操作は自動テストだけでは代替できない。したがってv15は署名APKの独立検証後も、V15-R01〜R05が受入されるまで正式版にしない。

## 署名前品質ゲート

| 検証 | 結果 |
|---|---|
| ユニット・静的契約 | 26ファイル、79件合格、1件スキップ。時間型の停止経過、手動完了、Widget開始／停止、mini-card、必須先頭、サイズ安全性を含む。 |
| TypeScript | `pnpm check` 成功。 |
| Lint | `pnpm lint` 成功。 |
| 通常版クリーンAndroid生成 | versionCode 25。Widget Provider、開始／停止操作、mini-card drawable、旧Collection経路不在を確認。 |
| 本人用クリーンAndroid生成 | `com.app.focusflow.personal`、versionCode 15、専用scheme。停止時経過秒ブリッジ、Provider、全9つのmini-card／タイマーdrawable、禁止構造不在を確認。 |

本人用の署名APKはGitHub ActionsでKotlinコンパイル・署名後に独立検証する。ローカルのGradle本ビルドは、サンドボックス資源の安定性を理由に品質根拠として用いない。
