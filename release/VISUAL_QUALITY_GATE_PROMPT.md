# Focus Flow 表示品質ゲート用プロンプト

以下を、今後の修正依頼の先頭にそのまま貼り付けてください。

> **Focus Flowでは、コードが通ること、APKが署名できること、ProviderやResourceが存在することだけでは完了とみなしません。Widget、設定、Today、Todo、習慣、メモ、振り返り、その他、Plus、法務、サポート、起動、遮断、空・読み込み・エラーの各画面について、実際に表示されたスクリーンショットで視覚受入が合格した場合だけ、次工程・APK配布・Play配布へ進んでください。**
>
> **実装前に、各不具合を「再現条件／期待表示／実際の表示／表示サイズ／テーマ／文字サイズ／データ状態／判定者」でテストケース化してください。テストケースには、短文・長文、空・1件・2件以上、必須・通常、完了・未完了、ライト・ダーク、コンパクト・標準・大きめ文字、透明度0・50・100%、小・中・大Widgetを必ず含めてください。**
>
> **Android Widgetは、初回追加直後、アプリを開いた後の同期後、ホーム画面へ戻った後、端末再起動後のそれぞれで実画面を確認してください。「ウィジェットを表示できません」「ウィジェットを追加できません」、白紙、文字切れ、重なり、半端な行、過大な空白、低コントラスト、誤った行へのチェック移動、詳細遷移との混線が1件でもあれば不合格です。原因を特定して修正し、同じテストケースを最初から再実行してください。**
>
> **自動テストは、①状態データ・ID・PendingIntent・テーマ値・RemoteViews resourceの単体／統合テスト、②クリーンAndroid生成、③署名APKのManifest・resource・署名解析、④エミュレータまたは実機で取得したスクリーンショットのレイアウト・文字・色・操作結果の比較、の四層で実施してください。XMLやAPK解析だけで「表示できる」と判断することを禁止します。端末ランチャー固有のWidget表示は、最終的に対象実機のスクリーンショットで合格させてください。**
>
> **各テストケースについて、期待状態と実際のスクリーンショットを対応付け、合格・不合格・未検証を記録してください。未検証または不合格が残る間は、APKを「検証候補」としても配布せず、修正・再テストを続けてください。「修正済み」「動作する」「問題ない」と報告できるのは、すべての必須ケースが実機で合格した後だけです。**
>
> **デザイン判断では、視覚チェックは20dp程度、タップ領域は48dp以上、本文は背景との十分なコントラスト、タイトルは1行省略、補足は収まる短い情報だけ、行は均一、区切りは明確、カードの余白は内容量に応じることを必須としてください。ライト／ダークは、本文、補足、面、境界、必須、完了、無効、選択、入力、モーダル、空・エラー状態まで別々に合格させてください。**
>
> **公開・購入・支払い以外は自律して進めて構いませんが、Play Consoleへアップロード・公開する直前だけは確認してください。テストの失敗、実機未検証、設計上の限界は隠さず、次に必要なスクリーンショットと再現手順を明確に報告してください。**

## 最低限の必須視覚テストケース

| ID | 対象 | 条件 | 合格条件 |
|---|---|---|---|
| V-01 | Widget追加 | 新規追加直後 | エラー表示・白紙・クラッシュがなく、初期面または一覧が読める |
| V-02 | Widget同期 | アプリ起動後にホームへ戻る | `ウィジェットを表示できません`へ置換されず、データが更新される |
| V-03 | Widget密度 | 小・中・大、空・1件・2件、短文・長文 | 内容高に収まり、切れ・重なり・半端な行・過大空白がない |
| V-04 | Widget操作 | 上段・下段の本文／チェック／ヘッダー | 詳細、該当行だけの完了／復元、Todayが混線しない |
| V-05 | Widgetテーマ | ライト・ダーク、透明度0・50・100%、文字サイズ3段階 | 本文・補足・境界・チェック・必須・完了を判読できる |
| A-01 | 表示と言語 | ライト・ダーク、全フォント、文字サイズ3段階 | 選択肢、見本、説明、選択マーク、境界が読め、白文字と白面が重ならない |
| A-02 | 本体主要画面 | Today、Todo、習慣、設定、モーダル、空状態 | 面・本文・補足・入力・境界・無効・完了を判読できる |

> **重要:** Android Widgetの表示可否は、APK構造の自動検査だけでは証明できません。対象ランチャーがRemoteViewsをどう描画するかは実機確認が必要です。そのため、実機スクリーンショットがないビルドは「未受入」であり、配布不可と扱います。
