# Focus Flow v13 — 高密度Widget・ダークモード再設計仕様

## 1. 改訂の背景と目的

実機で、Widgetの各項目がカードとして過度に大きくなり、複数項目を一覧できないこと、チェックが行の視覚的中央からずれること、Todoだけが大きく見えること、アプリ内のダークモードで文字が読めない箇所があることを確認した。本仕様はこれらを局所的に補修せず、**ホーム画面で短時間に確認・完了するリスト**としてWidgetを再設計し、アプリ全体の色・文字の契約を統一するための要件である。

Androidの公式設計は、Widgetをサイズ変更可能なレスポンシブな情報面として扱い、割り当てられた領域を有効に使うこと、デバイスのライト・ダークテーマとコントラスト設定へ適応することを求めている。[1] Collection Widgetは`ListView`で垂直スクロールする多数の同種要素に適しており、行ごとの操作はテンプレートとfill-in Intentで分離する。[2] TickTickの公式案内も、タスクを確認・アクセスするWidgetと、習慣を確認・記録するWidgetを主要な用途としている。[3]

## 2. 要件

| ID | 要件 | 受入基準 |
|---|---|---|
| W-00 | Widgetを正常に追加できる | Launcherから「Focus Flow · Today」を追加すると、Providerの初期レイアウトが表示される。`APPWIDGET_UPDATE` Receiver、Provider metadata、`initialLayout`、RemoteViews Serviceのいずれかの不整合で「ウィジェットを追加できませんでした」にならない。 |
| W-01 | Widgetは単一のリスト面とする | 各項目に独立した大きなカード背景を作らず、Widget本体の面の中に行と区切り線だけを置く。 |
| W-02 | 高密度を優先する | 標準文字では1行48dpを基本高とし、標準の最小Widgetで見出しを除き2件以上、拡大時はその分だけ多くの項目を表示する。 |
| W-03 | チェックを正確に中央へ置く | 視覚チェックは20dp、操作領域は48×48dpとし、行の垂直・水平中央に固定する。本文・チェックのタップは重ならない。 |
| W-04 | Todoと習慣の型を揃える | Todo・習慣でタイトルのベース文字サイズ、行高、太さ、チェック位置を共通にする。種別の違いは小さな補助記号だけで示す。 |
| W-05 | 文字サイズ設定と同期する | Widgetはアプリの`fontScale`を唯一の既定値とする。`compact`・`standard`・`large`の全設定でタイトル、補足、行高、最大行数を同じ規則で変え、端末のフォント倍率だけで不意にカードが巨大化しない。 |
| W-06 | 必須・時間帯を密度を損なわず示す | 必須は左端のアクセント線と短い補助ラベルで示し、時間帯は存在するときだけ小さい第2行へ置く。空の補足行、必須専用の余白、空白カードは作らない。 |
| W-07 | 状態を一操作一結果にする | チェックは完了／復元のみ、本文は該当詳細、ヘッダーと空白はTodayへ遷移する。時間前はロックを示して状態を変更しない。 |
| D-01 | テーマ契約を共通化する | 背景、面、強調面、本文、補足、境界、主要操作、警告、危険、完了済みの色をテーマごとに定義し、直接のライト専用16進色で本文を描かない。 |
| D-02 | 全画面でダーク可読性を保証する | Today、Todo、習慣、メモ、振り返り、その他、設定、Plus、法務、プライバシー、サポート、起動、遮断、モーダル、空・読み込み・エラー、Widgetをライト・ダークで確認する。 |
| D-03 | Widgetもテーマに追従する | Widget本体、見出し、行、区切り、タイトル、補足、必須線、完了・ロック・チェックがアプリ選択テーマと外観設定に追従し、背景が明暗どちらでも文字が読める。 |
| D-04 | Widget行の可読性は明示的に保証する | 行タイトル・補足・空状態の色は、Widget本体の背景色から計算・検証した高コントラスト値を使う。アプリ共通パレットに欠損値や古い状態があっても、行本文を背景に近い色で描画しない。 |

## 3. 画面・状態設計

Widgetの見出しは「今日の項目」と集中制限の短い状態だけを表示する。行の主情報はタイトル、補助情報は必須または時間帯のどちらか一つとする。行は1件につき一つの水平帯であり、タイトルは原則1行で末尾を省略する。長いタイトルでも行高を無制限に増やさず、詳細画面で全文を確認する。完了項目は取り消し線と控えめな補足色で示し、読める本文コントラストを維持する。

テーマ処理では、背景に対して本文・補足・境界を個別に選び、固定の白い面や固定の濃い本文を全テーマへ流用しない。Android公式は、ダークテーマで固定背景色と既定文字色の組合せを避け、Widgetをライト・ダークの両方で検証するよう示している。[4]

## 4. 状態遷移

| 起点 | 操作 | 結果 | 戻り先 |
|---|---|---|---|
| Widget行のチェック | 未完了をタップ | 完了状態へ更新。アプリ画面は開かない。 | Widgetに留まる |
| Widget行のチェック | 完了済みをタップ | 復元状態へ更新。アプリ画面は開かない。 | Widgetに留まる |
| Widget行の本文 | タップ | 該当Todo／習慣の詳細を開く。 | 閉じるとToday |
| Widget見出し・余白 | タップ | Todayを開く。 | 通常のタブ遷移 |
| ホーム画面のWidgetピッカー | 「Focus Flow · Today」を追加 | 初期レイアウトを表示し、同期後は現在のTodo・習慣リストへ更新する。 | ホーム画面 |
| ダークテーマ | 全画面・全状態 | 背景と本文・補足・ボタン・入力・無効状態が見分けられる。 | 同一画面・同一操作文脈 |

## 5. テスト・実機受入

自動テストは、48dp行、48dpチェック領域、1行タイトル、アプリ文字サイズの同期、必須線、空補足の非表示、ライト・ダーク双方のパレット受け渡し、固定のライト専用本文色の禁止を検証する。加えて、生成済みManifestのReceiver・Provider metadata・RemoteViews Service・`initialLayout`資産、ライト／ダーク行本文の背景との差を検証する。通常版・本人用版のクリーンAndroid生成と署名ビルドを実行する。

実機では、まずWidgetピッカーからProviderを追加できることを確認してから、小・標準・拡大へリサイズし、Todoのみ、習慣のみ、混在、必須、時間帯、長文、完了、ロック、透明度0・50・100%、ライト・ダーク、文字サイズ3段階を確認する。アプリ本体は各画面の通常・空・読み込み・失敗・モーダル・戻るをライト・ダークで確認し、文字と背景が識別できない箇所を残さない。
