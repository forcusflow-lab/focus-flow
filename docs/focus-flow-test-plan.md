# Focus Flow テスト計画・受入基準

## 1. 自動検証の方針

変更ごとにTypeScript、Lint、対象ユニットテストを実行し、主要な修正後に全回帰を実行する。Androidネイティブ資産は、Expo Android生成、Widgetレイアウト構造検査、Androidプラグインのコピー契約で確認する。GitHub Actionsはユーザーが実行するため、本作業ではworkflowを変更せず、実行可能なソース状態まで整える。

| レイヤー | 検証対象 | 合格基準 |
|---|---|---|
| 型・静的解析 | TypeScript、Lint、差分チェック | 型エラー、Lintエラー、空白・競合マーカーがない。 |
| ドメイン | 期限、必須、週間進捗、時間計測、サブタスク | 同じ入力に対しToday・Widget・制限判定が同じ結果になる。 |
| UI契約 | カード、フォーム、設定、テーマ、起動 | 重要文言が存在し、操作イベントが競合せず、テーマトークンを使う。 |
| Widget | 静的RemoteViews、ID、drawable、操作キュー | 重複項目を表示せず、全行と操作IDが生成後のAndroidプロジェクトに存在する。 |
| Android生成 | Expo prebuild、プラグイン、Manifest | Provider・Service・Activity・リソースが一貫して登録・コピーされる。 |
| 実機受入 | Widget配置、制限遮断、通知、購入、戻る | 指定端末で主要導線が完了し、クラッシュ・文字欠け・誤遷移がない。 |

## 2. 主要受入ケース

| ID | シナリオ | 期待結果 |
|---|---|---|
| A-01 | 期限切れTodoを作成しTodayを開く | Todoは必須として表示され、ラベルは「必須」、期限は「期限切れ」と全文で表示される。 |
| A-02 | Todoカードのチェック領域を押す | 詳細画面を開かず、完了状態だけが切り替わる。 |
| A-03 | Todoカード本体とサブタスクChevronをそれぞれ押す | 本体は詳細を開き、Chevronだけがサブタスク一覧を開閉する。 |
| A-04 | WidgetでTodoを完了後、本体を開く | 親Todoの完了状態が同期され、サブタスク・メモ・期限が消えない。 |
| A-05 | 回数・時間型習慣をToday・習慣・Widgetで操作する | 同じ日次進捗・時間状態が反映され、開始・停止・再開が可能である。 |
| A-06 | テーマ、明暗、文字倍率、フォントを変更する | 全画面とWidgetで読めない文字、重なり、切り詰めがない。 |
| A-07 | 選択アプリを集中制限中に起動する | 一度だけ遮断UIを表示し、「今日の項目を確認する」でTodayへ遷移する。 |
| A-08 | Widgetをランチャーへ追加・サイズ変更する | Widgetが追加され、1・2・3・5行のサイズバケットで安全に更新される。 |
| A-09 | 設定、法務、サポートを開きAndroid戻るを押す | 一つ前の画面または設定ホームへ戻り、アプリが終了しない。 |
| A-10 | GitHub ActionsのAndroid workflowを手動実行する | prebuild、署名、AAB生成、証明書照合、artifact出力が成功する。 |

## 3. 実機受入チェックリスト

実機では、ランチャーWidgetの追加・サイズ変更・テーマ変更、アクセシビリティ許可、遮断UI、バックグラウンド復帰、通知、購入／復元、Android戻るを確認する。実機でしか確定できない項目は、ユーザーがGitHub Actionsから署名ビルドを実行した後に評価する。
