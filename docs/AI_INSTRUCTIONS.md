# AI Development Instructions

このドキュメントは、Focus Flow プロジェクトを今後開発・保守するすべてのAIエージェント（Antigravity, ChatGPT, Claude, Manus など）向けの共通開発指示書です。

---

## 最初に読むもの

作業を開始する際は、まず以下のドキュメントを確認してください。

1. **`docs/AI_INSTRUCTIONS.md`**（本ドキュメント：基本行動規約）
2. **`docs/PROJECT_CONTEXT.md`**（プロジェクト全体像・構成・主要ファイル）
3. **`docs/UI_RULES.md`**（UI設計規約・マスターコンポーネント基準）
4. **`docs/BACKLOG.md`**（既知の課題・優先度付きタスク管理）

> [!IMPORTANT]
> **トークン・時間節約の原則**:
> プロジェクト全体のコードを毎回最初からすべて読むことは禁止です。
> 今回のタスクに直接関係する部分のみをピンポイントで調査・確認してください。

---

## 基本方針

1. **既存機能を壊さない**:
   - 既存の画面遷移、タップ操作、データ構造（`types.ts`）、Android連携ロジックを破壊してはならない。
2. **最小限の変更を優先**:
   - 目的達成に必要な最小限の行数・ファイル数のみを変更する。
3. **不要なリファクタリングの禁止**:
   - タスクの指示に含まれないリファクタリング、コードスタイルの自己判断による書き換えは行わない。
4. **不要なライブラリ追加の禁止**:
   - 既存の標準機能・導入済みパッケージ（`@expo/vector-icons`, `react-native`, `@react-native-async-storage/async-storage` 等）を最大限に再利用する。
5. **推測による実装の禁止**:
   - 既存の実装・シグネチャ・コンポーネント構造を必ず確認してから修正する。
6. **タスク外コードの不変**:
   - 今回依頼された範囲外のコードには触れない。

## UIルール

- UIを変更・追加する場合は、必ず **`docs/UI_RULES.md`** を基準とする。
- **Todoカード（`components/focus-flow/item-cards.tsx` の `TodoItemCard`）をこのアプリのUIマスターコンポーネント（デザイン基準）** として扱う。
- Habitカード、設定画面の各項目、Android Widget 等のすべてのUIは、Todoカードの構造（角丸、余白、カラーアクセント、バッジ、チェックUI、タイポグラフィ）と言語を一貫させる。
- **特に注意すべき過去のバグ**:
  - 「習慣カードを押したら曜日展開してしまう」問題の再発防止。カード本体タップ（詳細/編集へ遷移）と展開ボタン（曜日進捗トグル、`stopPropagation` 必須）は絶対に分離を維持する。

## Gitルール

1. **作業開始前**:
   - `git status` と `git branch` を確認し、現在のブランチと作業ツリーの状態を把握する。
   - 他の未コミット変更や作業中の変更を勝手に削除（`git checkout -- .`, `git reset --hard` 等）しない。
2. **作業完了後**:
   - `git diff` / `git status` で意図した変更のみが含まれているか確認する。
   - 必要な検証（型チェック・関係するテスト等）を実行する。
   - 変更内容に応じた簡潔でわかりやすいコミットメッセージでコミットする（例: `docs: add AI development context and UI guidelines`）。
3. **Pushについて**:
   - pushは現在の実行環境で安全に実行できる場合のみ行う。認証エラーや権限不足が発生した場合は無理に変更・強行せず、コミット完了の状態で停止しユーザーへ報告する。
4. **セキュリティ**:
   - 認証トークン、APIキー、個人情報、秘密鍵をログやファイルへ表示・保存しない。

---

## テストルール

- 今回変更した内容に直接関係する検証を優先する。
- 毎回プロジェクト全体の重いテストを無意味に繰り返さない（トークンおよび計算リソースの節約）。
- ただし、型定義や共通コンポーネントなど広範に影響する箇所を変更した場合は、以下のコマンドで整合性を確認する：
  - `pnpm check`: 型チェック
  - `pnpm lint`: 静的解析
  - `pnpm test`: 単体・契約テスト

---

## GitHub Actions

- AIエージェントがGitHub Actionsの実行状況をポーリング・監視し続けない。
- push後のビルド・テスト結果は、原則としてユーザー自身がGitHub上で確認する。
- 万が一Actionsが失敗した場合は、ユーザーから提供されたエラーログをもとに原因箇所を特定し修正する。
